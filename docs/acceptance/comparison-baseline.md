# 差异评审输入基线（按需）

差异评审开始前，冻结每个输入的路径、用途、版本、原字节 SHA-256、角色和相互关系。至少区分当前试跑产物、实际被验收的产物、视觉/交互参考、文档参考和PRD；某一角色不存在时明确写“不适用”及原因。

HTML、Markdown、PRD、截图、验收报告和工具证据分别登记。先核对HTML内嵌文档与外部文档的哈希/规范化匹配，再决定哪些内容可共同作为同一基线。HTML与文档不匹配时可以继续审查，但必须拆开报告：视觉参考只支撑视觉/交互观察，文档参考只支撑业务/交付依据，不能把一方的页面或业务假设倒写成另一方要求。

页面、状态、组件、图示数量只能用于范围提示，不用于质量分数或直接推导缺失。不同版本先按页面职责、状态语义、组件变体、入口目标、返回上下文和数据断言建立语义映射，再比较差异。旧验收结果只能绑定其实际被测产物哈希；修复版或重建版必须建立新批次。

可用[示例协议](comparison-baseline.example.json)登记；它是评审输入协议，不是项目主交付物、业务规则或验收结论台账。必要时用工具核对文件路径和原字节哈希；工具通过不证明输入关系或设计语义正确。

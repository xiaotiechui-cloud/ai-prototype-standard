# 数据与交易：执行细节

读取 [模式入口](README.md)；权威为 [core3](../../standards/core.md#s-3)、[runtime13](../../standards/runtime-and-build.md#s-13)、[admin12](../../standards/profiles/admin.md#s-12)及项目04/05。金额、权限、状态和重试依据不能从按钮名称猜测。

| 能力 | 契约要点 | 端到端检查 |
| --- | --- | --- |
| 配置闭环 | 生产方、唯一字段路径、草稿/生效版本、合法空值、失效对象、消费端 | 后台改内容/顺序/规格价格→各端实际读取；合法清空不回退样例 |
| 保存/生效 | 按admin12.11选择模块生效契约、写入边界与历史版本 | 草稿模块保存后前台不变，发布失败/成功分别检查；直接保存依契约，不强增发布；历史快照另核对 |
| 交易/恢复 | 稳定订单ID、资格重验、幂等、支付尝试、结果未知、恢复入口 | 每端分别建/恢复同单；未知先核查，重入/连点不重复建单；已付未交付仍显示处理中 |
| 状态映射 | 支付/交付/售后分开，中文标签和允许动作、统计同源 | 同事实在列表/详情/角标/后台一致；标签变化不改底层状态含义 |
| 操作副作用 | 查看/导出/开始处理/确认完成分别声明读写和产生物 | 查看不建批次；导出不代表处理完成；取消不提交；部分失败逐对象可辨 |
| 权限/审计 | 执行前重验、数据范围、敏感信息、原始before与after | 撤权/对象变化后再提交；B对象操作不影响A；审计旧值不可取修改后的同一引用 |

确认范围只按12.10判断，低风险可逆例外不得取消项目已批准的更严格策略。真实外部服务与模拟结果分别标记；供应商、支付或上传等未接入时留依赖，不能凭界面宣称可上线。

本商城“已完成/已关闭”映射已明确，但只在 [商城项目契约](../../reference/projects/steam-store.md) 定义，不强迫其他业务采用同名状态。按 [quality29](../../standards/quality-and-evidence.md#s-29) 保存操作前后事实/审计、失败和影响回归证据。

定向夹具：按[business24.5](../../standards/deliverables-business.md#s-24)测空/0/false/缺失与失败；按core3.4测非等差规格价和修改目录后的旧单；按admin12.13测有权开B后撤权/状态改变再提交，以及审计before与after确实不同。组合导出/建批次依runtime13.3单独核对产生物与写入范围，不由toast推断外部完成。

有父子交易或批次时，再测A/B成员一项完成、另一项处理中/失败/取消、空批次与重复回执；父状态按core3.4声明的聚合条件更新，独立封批与交付完成分开核对。不得由聚合检查隐式增加全局原子提交。

# 体验问题与发散调整

以下把用户的七项观察与源码证据分开。证据只定位短选择器、组件 ID 或行号，不复制原型源码。

## 1. 移动端滚动条

**结论：**试跑 3.0 的移动业务区保留纵向滚动（试跑第 61 行），但没有对应隐藏滑块的规则。最终版保留 `.phone-body` 的滚动能力，并对画布内部滚动容器隐藏滑块（最终版第 137–146 行）。若“右侧滑动条”指浏览器页面外层滚动条，静态样式不足以确认；需要真机/浏览器分别检查页面滚动与设备画布内部滚动。

**调整：**只隐藏手机壳、内容面板及必要的内部列表滑块；保留触控/滚轮滚动、焦点可见和可到达内容。横向排序栏如仍需横向滚动，应单独验证不产生整页横向溢出。不要使用 `overflow:hidden` 代替隐藏滑块。

## 2. 模拟身份控制冗余

顶部“APP/WEB/ADM”是原型终端切换；平台 A/B/C 是来源平台/账号上下文；登录、实名成年、手机号和协议是购买前置条件。三者不是同一维度。问题在于评审工具把状态快捷入口、身份前置条件和平台环境混排，初看像重复切端。

**调整：**保留端切换和必要的平台账号切换；移除重复的整页状态快捷切换。将身份区改为清晰的测试前置条件，至少包括未登录/已登录、未实名/已成年/未成年/未知、手机号未绑定/已绑定、协议未同意/已同意；点击购买仍需按业务优先级逐项进入流程。模拟控件不应绕开流程，也不应向业务状态伪装成真实平台回调。

## 3. 管理后台拖拽排序

最终版包含数个可拖拽列表，但当前证据不能覆盖所有后台“排序”字段或按钮。拖拽必须有明确把手、拖动中插入位置反馈、键盘替代方式、保存/发布反馈及取消/恢复路径。单纯给整行加 `draggable` 会和行内点击、选择、滚动冲突。

**调整：**凡语义是人工维护展示优先级的后台列表，统一使用“排序”把手拖拽；完成后更新数组顺序并显式保存/发布。数值优先级、时间升降序、销售量等业务查询排序继续保留选择器/字段，它们不是人工编排顺序。触屏端提供上移/下移作为拖拽的可访问替代。

## 4. 系统一级菜单为空

试跑已登记权限管理与操作记录页面（`ADM-RBAC-01`、`ADM-AUDIT-01`，第 817–818 行），角色允许页见第 1572–1580 行。渲染器过滤后仍创建分组，只有搜索时才删除空组（第 2449–2454 行）。运营、客服、财务角色因此可能看到空的“系统”标题；管理员可看到子项。

**调整：**无任何可见子项时不渲染该组；系统权限只授予管理员或具备相应权限的角色。对于当前页属于无权访问的情况，应显示明确无权限状态并提供返回，不通过空菜单暗示功能不存在。服务端权限校验仍是最终保障。

## 5. PC 布局

试跑评审器使用固定 `384px + 主画布` 的两列布局（第 44 行）；桌面商城页自身另有 1280px 内容宽度限制（第 266 行）。这两种布局要分别评估：一是评审器主画布是否被固定侧栏压窄，二是商城商品详情的媒体/信息/购买卡是否充分利用宽屏。

**调整：**评审器在大屏使用可调/可收起检查面板，默认优先显示业务画布；在 1280px 附近自动折叠，窄视口切成单列。商城页面使用受控最大宽度、清晰网格和稳定购买区；商品详情按媒体/说明与价格/购买区域分栏，避免过宽行文及窄列堆叠。验收视口至少 1920、1440、1280、1024 和移动端。

## 6. 弹层以原型界面为定位范围

试跑手机壳 `.phone` 样式（第 53 行）未创建定位上下文，移动遮罩 `.app-mask` 用 `position:absolute; inset:0`（第 218 行）；PC `.webcanvas`（第 258 行）与 `.webmask`（第 299 行）也没有可见的局部定位宿主。代码结构解释了遮罩可能相对整个文档定位的现象。最终版手机壳显式 `position:relative`（第 132–134 行），`.modal-mask` 作为壳内绝对定位层（第 680–686 行）。

**调整：**把遮罩插入当前 APP/WEB 设备画布内，宿主设为定位上下文；横向/纵向居中按画布尺寸计算。移动底部面板继续贴设备底边；PC 对话框居中，右侧抽屉贴画布边缘。关闭遮罩、Esc、返回键和焦点恢复按层级一致处理。最终仍需浏览器实测。

## 7. 主流通用 UI

“通用风格”不能靠更换颜色实现。项目已采用灰度低保真方向，应优先改善信息层级和一致性：页面标题/说明、筛选区、表格密度、主次按钮、状态反馈、表单校验、空/错/加载状态、抽屉与确认弹窗。移动端触控目标与桌面密度分别处理；颜色不作为唯一状态编码。

## 发散发现

- 把“测试状态”与“业务身份条件”放同一控制区会诱导评审直接跳状态，漏掉购买校验优先级、现场保留、取消和返回分支。
- 菜单展示、路由可达和操作授权需分开验证。隐藏导航不应被当成权限控制。
- 后台排序要区分“人工编排顺序”与“查询结果排序”，否则统一拖拽会误伤列表查询能力。
- 页面注册、组件定义和状态计数不是交互可达性的证明；至少要为主路径、权限边界和异常恢复保留可执行回归。
- 单文件体积增长会加重下载、检索和模型上下文成本。后续评审继续以结构清单/哈希/局部证据为入口，不把 HTML 或内嵌文档复制到对话。

# 项目调整建议与待审规则

本文件将反馈转成可审阅实施项。两份输入原型保持只读；以下是调整建议，不表示已经修改或浏览器验收。

## 推荐实施顺序

| 顺序 | 工作项 | 验收结果 |
| --- | --- | --- |
| P0 | 将 APP/WEB 遮罩限制在设备画布；补齐手机和桌面宿主定位 | 每类弹层均在对应设备画布居中/贴边，原型外页面不被遮罩 |
| P0 | 过滤零子项后台分组，权限菜单按角色正确展示 | 运营、客服、财务、管理员各自菜单无空组且无越权入口 |
| P1 | 隐藏手机画布内部滚动条，保留纵/横向滚动能力 | 小屏内容可滚到末项，整页不产生意外横向溢出 |
| P1 | 拆分端切换、平台环境、业务前置条件；删除冗余状态快捷入口 | 购买资格仍能逐分支测试，但快捷按钮不绕过主流程 |
| P1 | 统一后台人工排序拖拽把手和保存语义 | 所有人工编排列表可拖动、可保存/发布、可恢复并有键盘替代 |
| P2 | 调整评审器与商城 PC 断点/内容分栏 | 1920/1440/1280/1024 宽度下主内容可读，无重叠、遮挡或无谓留白 |
| P2 | 建立灰度线框组件基线 | 表格、筛选、输入、按钮、状态、弹层具有一致间距、层级和交互反馈 |

## 可直接作为本项目改动目标

1. 本项目原型滚动容器保留滚动，手机设备画布内部不绘制多余滚动条。
2. 本项目身份模拟仅用于购买业务前置条件测试；端切换和来源平台选择分开；删除通用页面状态快捷按钮或移入独立的 QA 工具区。
3. 管理端人工维护的展示顺序使用显式拖拽把手；结果集的业务排序和明确的优先级字段不强行改成拖拽。
4. 当前角色没有任何可见子项的菜单组不展示；系统配置和审计入口按管理员授权。
5. 当前原型画布是弹层遮罩的布局宿主；禁止遮罩以整个 HTML 文档作为业务弹窗定位上下文。
6. PC 评审器优先保证业务画布宽度；屏幕不够时检查面板折叠或转为单列。
7. 保持项目灰度线框视觉方向，修正表格、筛选、按钮和反馈的一致性。

## 跨项目候选规则（待审）

| 候选 | 适用边界 | 需要审议的具体决策 |
| --- | --- | --- |
| `R-SPR-01` 滚动条呈现 | 客户端/嵌入式原型，不约束内容滚动能力 | 是否将“内部滚动容器默认隐藏视觉滑块”列为通用默认，并允许平台可发现性要求覆盖 |
| `R-LAYER-01` 原型弹层宿主 | 有设备画布/嵌入容器的交互原型 | 是否要求遮罩默认覆盖当前业务画布，而非浏览器视口；明确全屏弹层的例外 |
| `R-ADM-01` 空权限分组 | 角色过滤式后台导航 | 是否统一隐藏零可见子项分组；审计/配置页由授权角色决定，不保留空标题 |
| `R-ORDER-01` 人工排序 | 可人工维护展示顺序的数据集合 | 是否要求统一拖拽把手及持久化反馈；不覆盖数值优先级、时间排序、指标排序，并提供触屏/键盘替代 |
| `R-SIM-01` 评审模拟器 | 多端业务原型 | 是否要求区分终端、外部平台身份、业务前置条件和页面状态；限制模拟器绕过主流程 |
| `R-RESP-01` 桌面工作区 | 桌面商城和原型评审器 | 是否只规定职责、断点行为与密度检查，不固化本项目 384px 侧栏或商城分栏尺寸 |

按规范仓库维护流程，候选规则保存在待审评审目录，不写入活动规范、不改版本号，也不提交发布。最终版作为项目设计参照，不代表所有页面结构适用于其他业务。

## 明确不应自动推广

- Steam 商品详情的具体分栏比例、广告顺序、设备外框大小和项目专属页面。
- 所有后台列表一律拖拽，包括按价格/时间/销量排序的查询结果。
- 无条件隐藏整个浏览器页面的滚动条或禁用页面滚动。
- 通过前端隐藏菜单替代服务端鉴权。
- 为了对齐最终版数字而机械增删状态或组件定义。

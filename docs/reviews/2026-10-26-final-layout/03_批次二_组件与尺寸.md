## L-04 端与密度决定控件尺寸

来源：L648 `.btn`、L653 `.inp` 最小高 44；L385 `.mini` 最小高 34；后台一般控件最小高 40；移动作用域将小按钮/关闭按钮恢复为 44。现有 ui 7.3 已有下限；本项补同组统一密度和桌面默认档，不降低原要求。

**建议正文（ui 7.3）：**

控件应以端和密度变体确定统一尺寸，而非随按钮文字或单页补丁改变。同一操作组内输入、选择和普通按钮应使用同一高度档。

| 场景 | 默认 | 可用紧凑档 | 处理方式 |
| --- | --- | --- | --- |
| 移动业务交互 | 热区至少 44×44px | 不降低热区 | 图标视觉尺寸可小，外部交互容器补足；相邻热区不得重叠 |
| 桌面业务控件 | 最小高 40px | 最小高 36px | 同页/同组统一；长文允许增高 |
| 后台常规表单/筛选 | 最小高 40px | 无新增低于 40 的常规档 | 表格内紧凑操作按既有 34px 档 |
| 后台紧凑表格操作 | 最小高 34px | 无更小默认档 | 保留可辨文案、焦点和操作间隔 |
| 评审工具 | 最小高 40px | 不新增 | 与业务控件分开 |

尺寸为 CSS px；声明 min-height 不等于已证明实际热区。控件应允许字体放大、多行内容与输入法下可达，不能用固定 height 截字。视觉图标与热区分开登记；不把移动端 44px 高误报为已满足 44px 宽。

**例外：** 原生复选/单选小图形通过可点标签扩大热区；遵循已有平台约束和批准设计系统。源码中 22px 拖拽把手、30px 局部按钮、38px 后台输入不作为新默认。

**验收：** 实测外接矩形与命中范围；点击图标周边有效区域、键盘聚焦、触屏替代动作；加载/禁用状态不使同组布局跳变。源码 min-height 或 DOM 存在不足以标通过。

## L-05 文字、边框和圆角按语义分层

来源：L11 `:root` 基础色；L615 卡片 1px 细边；L648/L653 按钮输入为 0 圆角；L656 标签 12px；L659 提示 12px；L663 商品标题最多两行；L854 阅读正文 14px/1.8。最终版同时存在 11px/12.5px 等局部字级，且局部颜色不是现行全灰度规范。

**建议正文（ui 7.2/7.5；不改 7.1 色值）：**

默认使用现行灰度令牌与字号层级；补足语义用途，禁止照抄多个局部字号形成不受控的字级：

| 语义 | 默认字号/字重 | 说明 |
| --- | --- | --- |
| 页面标题 | 20px / 500 | 当前规则保持；不因某最终页面用 16px 自动降低 |
| 组件/区块标题 | 16～18px / 500 | 同级标题统一，项目固定所选值 |
| 业务正文、可编辑内容 | 14px / 400 | 不把主要内容降为辅助字级以容纳更多列 |
| 字段标签、辅助信息、业务提示 | 12～13px / 400 | 同类用途固定所选值 |
| 组件说明正文/表格 | 13px / 12px | 沿用现行说明规范 |
| 长文阅读正文 | 14px，行高建议 1.8 | 密集区域仍遵守现行行高范围与可读性要求 |

普通卡片、按钮、输入框使用矩形、1px 业务边框、0 圆角、无装饰阴影作为默认；选中、错误、焦点按既有状态语义处理，改变边框粗细不能推动布局错位。手机外框 22px、桌面预览外框 8px 与业务控件分开；移动居中弹层及底部面板可采用 16px 圆角变体，底部面板仅上侧圆角。后台任务弹层默认矩形；其他风格由批准设计系统覆盖。

同类内容卡应对齐媒体区、标题、附加信息和主要动作。摘要可限定行数，但完整内容须有明确可达位置；错误、金额关键位、关键规则和必要操作不得以省略号隐藏。媒体占位/加载/实际内容沿用同一尺寸或比例契约，替换时不使相邻主操作跳动。长宽比按内容类型确定，不能将商城封面高度推广到所有项目。

**例外：** 不以默认字级替代目标平台无障碍或已批准设计系统。源码状态彩色、11px 主要文字和负 margin 扩热区方案不自动推广；只提取语义和约束，不指定风险实现。

**验收：** 取计算字体、边框和圆角，与同组件变体一致；长中英文、长数字及放大文字不挤掉动作。摘要能到达全文；空/加载/失败切换不改为无结构空白页。不以“整体像最终版”代替逐项证据。

## L-06 弹层按任务复杂度分档

来源：L498 `.adm-dlg.confirm` 最大宽 400；L493 `.adm-dlg` 常规 560；L503 `.adm-dlg.form` 最大宽 920；L691 桌面业务任务弹层最大宽 600；L683/L684 移动面板限高。源码含 vh 限高，须转换为当前规范要求的业务宿主尺寸，不能照搬为整个 HTML 视口。

**建议正文（共同尺寸放 ui 7.5；web 11.4/admin 12.9 引用，运行生命周期继续归 STD-RT-001）：**

桌面/后台弹层应按内容任务选择最小可用尺寸档，而非按屏幕大就自动放大：

| 类型 | 建议最大宽 | 条件 |
| --- | --- | --- |
| 简单确认 | 400px | 对象、后果和少量动作；复杂详情不硬塞此档 |
| 普通任务/查看 | 600px | 普通信息、短表单或单一任务；将源码 560/600 收敛为一档建议值 |
| 复杂表单 | 920px | 多区块/多字段且有明确分组；短任务不使用此档制造空白 |

实际宽度不得超过当前业务宿主可用宽减两侧安全间距，默认每侧至少 16px。移动弹层不套桌面宽度，按内部业务区可用宽度布局；居中弹层建议每侧至少 12px，底部面板可贴边。

居中弹层默认高度不超过宿主可用高的 80%，移动底部面板可到 88%；短宿主、放大文字或键盘占位时，优先保留标题/关键动作并滚动正文，必要时采用经登记的宿主内全屏变体。不以整个 HTML 的 vw/vh 替代宿主测量。高度上限还须满足容器安全边距，二者取较严格者。

标题/动作区和正文分开，正文 `min-height:0` 并承担滚动。后台保存、提交与关闭仍按既有规则置于右上角，不因来源存在 `.df` 底栏样式迁移到下方。弹层关闭、焦点、遮罩、背景滚动、父子层行为全部引用 STD-RT-001，不设第二套规则。

**例外：** 项目确认设计、信息选择器/复杂图示等特殊任务可用其他宽度或全屏模式，登记宿主、宽高、必要性、动作位置和验收范围。920px 是最大宽建议，不是必需宽，更不是内容最小宽。

**验收：** 在常规、窄、矮宿主与长内容下，比较弹层相对宿主的边界/中心、实际安全边距、正文末端和动作可达；切换档位不能改变业务字段或状态。宽度分档、限高声明不替代浏览器实际测试。

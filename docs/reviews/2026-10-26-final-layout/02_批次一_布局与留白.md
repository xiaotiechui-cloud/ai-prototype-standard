## L-01 空间令牌按用途命名

来源：L26 `.shell` 外壳内边距 24；L63 `.rv-layout` 分栏间距 24；L617 `.row` 间距 8；L619 `.col` 间距 6；L615 `.card` 内边距与下间距 10；L664 `.grid2` 间距 10；L669 `.grid-auto` 间距 12；L671 `.split2` 间距 16；L381 `.fld` 标签间距 4。L148 移动卡片另有 9px/8px 覆盖，不能将 10px 宣称为该处最终计算值。

现有归口：ui 7.4/7.5 已要求组件间距一致，但未给空间用途表。本项是补充默认预设，不新增同义稳定 ID。

**建议正文（归入 ui 7.4）：**

项目未批准自有设计系统时，应按以下语义空间令牌组织布局。同类组件及相同密度变体应复用同一令牌，不为每页临时微调。CSS 变量名称可不同，但 01/03 中的语义和值应一致。

| 用途 | 建议令牌 | 默认 CSS px |
| --- | --- | --- |
| 标签与控件、正文与就近提示 | `space-label` | 4 |
| 同一小组内纵向内容 | `space-stack-tight` | 6 |
| 按钮组、行内控件 | `space-control` | 8 |
| 普通卡片内边距、同级卡片垂直间距 | `space-card` | 10 |
| 移动卡片网格 | `space-grid-mobile` | 10 |
| 桌面内容网格 | `space-grid-desktop` | 12 |
| 业务主辅分栏 | `space-column` | 16 |
| 评审外壳主要分栏与常规外侧内边距 | `space-review` | 24 |

紧凑卡片可用 8px 内边距并登记为共享变体；不以减少热区、压低字号或挤掉错误提示获取紧凑效果。手机壳内边距、桌面页面内边距、后台工作区内边距继续按各自权威章节，不用 `space-card` 代替。

不强制所有尺寸为 8 的倍数；光学对齐、图标与平台控件可保留有依据的局部值。超出预设时记录用途及组件变体；改变强制热区/固定画布须按原有例外流程，不借此放宽。

**验收：** 比较同类组件的相邻边界和计算 gap/padding，而非只搜索变量；标题、正文、提示、操作组的距离语义一致。必须分别标注 padding、gap、margin，不以边框之间的总距离冒充某个声明值。

## L-02 先选布局模式，再确定列数

来源：L257 `.desk-container` 内容最大宽 1200；L669 `.grid-auto` 自适应网格；L671/L672 主辅分栏及结算变体；其后按业务容器宽 860 收单栏；L313 `.admin-canvas` 左菜单＋弹性工作区。现有 web 11.2/11.7、admin 12.1、ui 8.4 已有基本规则，本项补可执行选择依据。

**建议正文（共同原则放 ui 7.4，端模式在 web/admin 归口引用）：**

在 01 为每类页面选定布局模式，记录主任务、区域职责和收拢条件。内容、表单、工具、后台四类空间不得因共用 CSS 类而机械互套：

| 模式 | 适用任务 | 选择与收拢依据 |
| --- | --- | --- |
| 居中单栏 | 阅读、步骤任务、普通表单 | 内容宽度上限与阅读长度；不为填满宽屏强行增列 |
| 主辅分栏 | 资料＋操作、明细＋汇总 | 两栏均能容纳长标题、关键字段、主要动作；不足时按任务顺序转单栏 |
| 自适应网格 | 同类、可比较的内容集合 | 按项目内容确定卡片最小可读宽度，再计算列数；最后一行不加虚构内容补齐 |
| 菜单＋工作区 | 后台管理任务 | 工作区可读宽度优先，菜单按已批准规则收起/转换；说明不得挤入工作区 |

主辅分栏应记录各栏最小可读宽度与比例，容器宽度不足“两栏最小宽度＋间距”时收拢；断点来自内容预算，不能直接复制评审外壳或示例断点。网格可按 `floor((可用宽+间距)/(卡片最小宽+间距))` 估算列数，并以长内容、金额和动作实际渲染复核；小于一列预算时调整为一列且保留内容，不用固定最小宽撑破容器。

默认沿用现行桌面内容上限 1200～1280px、页面内边距 24px；后台工作区约 20px。最终版 `.desk-body` 14px、后台 `16px 18px` 是紧凑实现参考，不能静默覆盖现行默认。

**例外与排除：** 不强制商城卡片、商品列数、广告、左资料右购买或结算组件出现在通用项目。不把 300px 卡片宽、860px 断点、1.15:1/1.35:1 列比例定为所有项目规则。既有设计系统优先，记录采用来源。

**验收：** 宽度应取业务容器内容区；固定菜单、内边距、边框、gap 分别计入预算。检查转单栏前后一个代表宽度以及当前端规定的代表视口，主动作可达、内容顺序合理、无主页面横向裁切。

## L-03 对齐依赖共同结构，不靠逐项偏移

来源：L381 标签＋控件纵向排列、L377/L383 操作组通栏；L260 `.page-head` 标题与辅助内容基线；L510 弹层标题栏操作组右对齐；源码模拟工具条说明强调标签/控件同行基线。

**建议正文（ui 7.5，admin 12.4 引用）：**

同组表单使用相同标签位置、控件高度与行内对齐基线。筛选区每个字段为“标签＋输入＋提示”的完整单元，长标签、错误提示可增高单元，不以固定高度裁去。同行控件应保持输入顶边或基线一致，操作组位置由区域结构决定，不以针对某字段的负 margin/定位修补。

默认标签与控件间距 4px，筛选字段网格间距 10px、操作组间距 8px；列数由最小字段宽决定，不将最终版三列作为必需列数。窄屏先换行或转单栏，不压缩控件热区。标题＋返回＋页面操作与全局导航分开，操作位置仍遵循当前端规则；后台保存/关闭仍在右上角。

长内容可推动区域自然增高。可选提示区不必预留大段空白；需要稳定基线时可使用共享网格结构，不要求所有字段无条件固定等高。纯展示键值与可编辑表单使用各自结构，不因样式相似混同。

**验收：** 对齐长标签、短标签、有错/无错、必填/只读组合；比较实际控件顶边、标签基线和左右边界。所有错误与说明可见且不覆盖下一行；键盘顺序随视觉布局合理连续。

## C-05 基础控件按同一结构和状态绘制

**建议条款：** 同组件同变体使用相同的标题/标签、内容、辅助信息和动作结构；样式从共享定义解析，不在实例偷偷覆写。视觉尺寸与点击热区分别记录。常态、悬停（适用指针端）、键盘焦点、选中、禁用、错误、处理中分别定义；不适用的状态写明原因，不补假业务。

| 组件 / 现有 PAT | UI 与尺寸约束 | 交互与状态约束 | 最少可观察验收 |
| --- | --- | --- | --- |
| 按钮 / ACTION-01～04 | 主动作深灰白字、次动作白底描边，沿用现行灰度；动作间距 8px；同组同密度，长文案换行后仍可用 | 文案说明实际动作；禁用有可读原因；提交中替换为进行态并防重复；链接跳转与写动作视觉/语义清楚 | 连点只执行一次；失败恢复可操作；触控与键盘均触发同一动作 |
| 图标按钮 / ACTION-01 | 图标可小，热区按端满足 L-04；有可访问名称；不靠 hover 才能发现关键动作 | 焦点可见；禁用时解释原因；相邻热区不重叠 | 点视觉边缘、Tab/Enter/Space，目标和动作一致 |
| 单行/多行输入 / INPUT-01～03 | 标签在控件外；占位不能替代标签；必填、帮助和错误分别占位；同表单标签方向一致；输入宽度受字段语义约束 | 输入仅更新草稿，保持光标/选择区；只读与禁用有区别；错误定位到字段，不以 toast 替代 | 连续输入/粘贴/输入法组合不掉字；错误保值；只读值可按需复制 |
| 搜索输入＋清除＋提交 / INPUT-01、TAG-02 | 输入与提交组成一组；清除按钮不挤压文字；历史/热门是可选模块，不为空凑标签 | 组合输入阶段 Enter 不误提交；按钮/键盘同校验；清除草稿不暗中提交；历史仅按已确认条件更新 | 空值、组合输入、重复词、详情返回、失败重试与已提交条件一致 |
| 单选/选项组 / CHOICE-01/02 | 整个选项为命中区；选中用描边/填充＋文字/标记表达；长标签换行；不靠胶囊或颜色表达唯一状态 | 同组唯一选中；不可用有原因；切换联动字段/摘要，不改无关字段；不静默选择 PRD 未允许的业务项 | 切换后显示值、计算值、提交值一致；选中项失效有明确恢复 |
| 复选/权限组 / CHECK-01/02 | 原生或等效语义，勾选框与文字标签同一命中区；长说明与勾选基线对齐 | 协议、一般多选、权限授权分别定义默认值与守卫，不能把协议默认不勾选扩成所有多选都必须空；支持必要的半选 | 点击文字可选；取消不改已保存值；无权限不能借全选绕过 |
| 标签/状态标记 / TAG-02、CARD-02 | 状态文本与可编辑标签外观区分；长值换行或有可达全文；删除热区独立 | 静态标签不伪装按钮；可删标签支持取消/确认约定；状态来自同源状态字段 | 名称、计数、实际过滤一致；删除不误触整个卡片 |

按钮与表单高度使用 L-04 档，正文和提示使用 L-05；不逐个组件另设 30/32/38px 高度。现有设计系统覆盖可登记新变体，但必须说明适用端/密度，不能把页面缩放当组件变体。

## C-06 导航、页签与筛选分工明确

**建议条款：** 导航改变页面/任务，页签改变已登记的视图或状态集合，筛选改变查询条件；三者外观与动作职责一致，不把每种入口都画成同一排按钮。

| 组件 / PAT | UI 结构 | 交互、恢复与验收 |
| --- | --- | --- |
| 移动顶栏 / NAV-01 | 返回区、标题区、右动作区；长标题不覆盖两侧动作 | 一级页按已登记导航定义决定返回；二级页回来源现场，不能固定跳首页；默认/长标题/有无右动作均验 |
| 移动底部导航 / NAV-02 | 固定在手机内部业务区底部，等宽或按已批准布局；当前项唯一且文字可辨 | 只放一级目的地；二级页是否显示按现行约定；切换不叠同页、不残留旧弹层；正文末项不会被覆盖。具体 Tab 数量/名称不推广 |
| 桌面顶栏 / NAV-03 | 标识/主导航/按需搜索/用户区分组；窄宽时按职责收拢 | 相同目的地不为填满组件重复放入口；返回后恢复必要查询。首页搜索与专用搜索页能否并存按职责依据，不做绝对禁止重复 |
| 后台菜单 / NAV-04 | 搜索、分组标题、二级项目、当前项；账号栏独立 | 无可见子项的分组不渲染空壳；搜索/权限/收起状态不出现不可达项目；菜单名称、页面标题、实际权限同源；窄屏适配按端规范，不把菜单横滑推广成表格横滑 |
| 状态页签 / FILTER-02 | 单一选中态、可选计数；长名称可换行或已登记收拢方式 | 计数与列表同口径；切换使用提交条件，分页按契约重置；单项不是强行补出第二项的理由 |
| 查询筛选 / FILTER-01/03 | 基础条件＋可选高级条件，查询/重置/刷新职责分开；标签/控件对齐 | 草稿与已提交条件分开；查询提交快照；重置同步已登记默认条件并防旧响应回写；刷新复用已提交快照；排序失败时选中条件与已显示数据不矛盾 |

排序选项的换行、收拢、下拉或已批准横向滚动按当前端规则和项目覆盖执行，不从最终版强制推广“5 项单行”。后台手工调整对象顺序按现行拖拽排序规则执行，不能与字段升降序混为一件事。

## C-07 卡片、列表、表格采用可追踪的数据结构

**建议条款：** 每条可操作记录必须绑定稳定对象 ID；点击卡片、行操作、详情层、请求参数引用同一对象。禁止用视觉行序号替代对象身份，或取不到对象时回退到第一条。

| 组件 / PAT | UI 契约 | 数据与交互契约 | 必验边界 |
| --- | --- | --- | --- |
| 内容卡/明细卡 / CARD-01、LIST-01、GRID-01 | 媒体、主标题、关键属性、辅助属性和动作层级固定；媒体比例在同变体内一致；长标题可到全文 | 卡片整块跳转与内部次动作分清事件边界；不可用态有原因；隐藏/缺失值不伪造数据 | 长中英文、缺图、0/1/多条、不可用、局部按钮点击不误跳详情 |
| 状态/个人信息/指标卡 / CARD-02～04 | 标签、值、单位/口径、时间范围、辅助说明分层；未知不同于 0 | 独立状态维度分别展示；同字段不各算一套；权限/身份变化清理敏感值 | 加载/未知/零值/失败/权限变化；指标与查询数据口径一致 |
| 业务记录列表 / LIST-03/04 | 主标识、关键内容、状态摘要、按状态可执行动作；长标识可换行复制 | 详情返回恢复查询、页码与滚动；继续加载追加不替换历史；末页不再发请求 | 加载更多失败保留已有项；同 ID 去重；动作随真实状态更新 |
| 后台表格 / TABLE-02 | 真表格；列按语义预算，标识/状态/金额/操作可辨；长表头换行；必要列不靠截断隐藏 | 表头、行、选择、行操作绑定同一数据集；入口按钮开详情，直接动作按风险确认；筛选/排序后不串对象 | 1440/1920适用工作区；长字段/无权限/窄操作列；无必须拖动才能完成主任务的底部横向条 |
| 分页/继续加载 / PAGE-01/02 | 总数、当前页/每页条数、前后动作/末页状态明确；只选需要的一种主方式 | 无效页禁用；查询变化按契约回第一页；删除末页最后一项后修正有效页；分页范围不暗变为跨页全选 | 0条、1页、末页、页大小变化、请求失败/迟到 |
| 行选择/批量 / BATCH-01 | 全选/半选、已选数、范围说明、清除与批量动作成组 | 区分当前页/跨页；确认绑定 ID 快照；部分失败逐项反馈；筛选变化按登记策略处理旧选择 | 0/部分/全部、换页换条件、权限变化、部分失败；显示数量等于实际提交数量 |
| 导出 / EXPORT-01 | 范围、字段/权限、任务状态、结果入口明确 | 不把点击即成功；发起/生成/可下载分开；失败可重试；按已提交条件或显式选择范围导出 | 空数据、无权限、超时、部分失败（适用时）、文件内容与声明范围一致 |

通用卡片不绑定“商品价格/订单号”等必填字段：项目在共享骨架上替换为自己的主标识、关键属性与动作。不能为了复用最终版制造钱包、营销位、支付、订单或后台权限能力。

## C-08 组件状态必须成套，视觉反馈与业务结果一致

**建议条款：** 对实际存在异步数据的组件，至少区分未请求、加载、有数据、成功为空、错误、权限不足和不适用；分页组件另分追加中、追加失败、末页。纯静态组件只声明适用状态，不强制造接口。状态切换不能以整页空白替代结构，也不能把所有无数据显示成“暂无数据”。

- 首次加载在目标内容区显示占位/文字；已有数据的刷新按登记策略保留并标明刷新，防止旧内容冒充新结果。追加失败只在底部给恢复入口，不清空已加载部分。
- 成功为空显示原因与可执行下一步；网络错误显示重试；无权限显示适用说明/申请或返回路径；未知状态显示未获知而非 0/成功。
- 禁用必须说明守卫原因，校验失败就地呈现，系统性失败留稳定恢复入口。短暂 toast 仅辅助轻量反馈，不承载唯一失败详情。
- 重试绑定失败时的对象和条件快照；新查询使旧响应失效；关闭/离开/换身份后不得靠迟到响应重建旧界面。

验收同时比对界面文案、状态字段、动作可用性、提交参数、结果与关联文档；不能只截图按钮变灰便认为防重复和权限控制已通过。

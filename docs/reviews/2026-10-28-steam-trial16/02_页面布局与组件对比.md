# 页面布局与组件对比

## 已稳定的共同特征

### 移动端

试跑16的 `_checks/layout_result.json` 记录：

- 外框 320×640 CSS px；业务区 288×592；
- 外框 2px `#8d939b`、22px 圆角、14px 内边距；
- `.app-body` 在业务区内滚动，滚动条不绘制，横向溢出隐藏；
- `.modal-host` 使用业务区绝对定位，弹层不以整个 HTML 页面为居中基准；
- 打开弹层时锁定业务区正文并做焦点进入/恢复。

最终版的 UI Profile 也使用同一组外框线条和移动画布约束。该部分已经具备通用化价值，继续保持“Profile 指纹 + 实测矩形”双证据即可。

### PC Web

试跑16使用独立的 `site-wrap`（最大宽度 1280px）、宽屏网格、详情左右分栏和宿主内居中弹层；W/ADM 在 1440 和 1920 视口的 `bodyOverflow` 均为 false。最终版使用 1200px 内容容器、同样的宽屏分栏思路和宿主内弹层。两者不需要统一成一个数字，但应保留“页面内容有最大宽度、列可收缩、弹层不超出工作区”的通用约束。

### 后台

试跑16具备左侧菜单、工作区、表格/抽屉和确认层，且 1440/1920 视口无横向溢出；最终版进一步固化了深色菜单、浅色工作区、菜单折叠、次要列收起和操作区保留的层级关系。该关系可以作为管理后台通用布局 Profile，但菜单名称和业务分组仍属于项目输入。

## 需要回归的差异

| 差异 | 证据定位 | 判断 |
| --- | --- | --- |
| W 顶部主导航职责较宽 | 试跑16 HTML `site-nav` 约第 1976 行：商城、搜索商品、我的订单、我的均列入主导航，客服另列用户区；最终版 `final-script-3.js:27-32` 将主导航收敛为商城/搜索商品，“我的”单独位于用户区 | 这是现有导航治理规则的执行回归候选，不是新增商城业务规则。生成门应检查“一级入口/账户服务入口/页面内快捷入口”职责是否重复。 |
| 试跑16固定外框高度 | 试跑16 HTML 第 58～60 行；最终版 `final-style-0.css:127-140` 使用同一外框视觉，但业务正文按容器滚动 | 当前尺寸符合用户已确认的手机壳效果；不要为了追最终版实现方式而删除外壳。只需持续验证业务区矩形、滚动边界和宿主定位。 |
| 组件定义总量较少 | `_data/summary.json` 与最终版历史 sidecar | 不是缺陷。必须按职责/变体/入口映射，不能设数量下限。 |

## 规范执行建议

1. 每个端的布局检查应同时记录“外层评审容器矩形、业务画布矩形、内容滚动矩形、弹层宿主矩形”，不能只记录页面是否渲染。
2. 每个一级导航项要有 `role`（内容、账户、服务、后台配置等）和唯一主入口；生成后扫描同一端同一视图中相同目标的重复入口。
3. 组件十节和页面实例已经有结构门控；继续要求实例的 `data-component/data-variant/data-ui-profile` 与注册表闭合，不能只检查“有十节”。
4. 视觉参考只约束 Profile 和布局职责，不把最终版的页面数量、具体菜单名称、业务商品卡数量提升为通用规则。

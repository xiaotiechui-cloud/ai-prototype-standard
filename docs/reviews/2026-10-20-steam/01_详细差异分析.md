## 2. 尺寸、画布和滚动

### D01 评审外壳：宽度不同，但“画布优先”已基本具备

**T：** 所有端共用最大宽 1480px、内边距 16px；移动双栏为 384px＋剩余宽度、间距 16px；WEB/ADM 使用通栏画布，说明在下方。

**F：** 移动外壳 1440px、桌面外壳 1480px、内边距 24px；移动双栏 384px＋剩余宽度、间距 24px。后台下方另分状态列与说明列。

**可复用：** 按端选择画布布局，让桌面表格/商品区先获得足够宽度；多余宽度给说明区。T 已做通栏，不能再把“桌面画布未通栏”列为缺失。16px 与 24px 的取舍只是基线一致性问题，尚无实测证据证明哪一个对所有项目更好。

**规范归口：** ui §7.4、§8.4 已覆盖。建议只在 Q1 确认后澄清默认值和例外，不再新增一套尺寸表。证据 S：T 26、39～45；F 22～28、59～126、5685～5692。

### D02 手机框：同为 320px，内容密度仍不同

**T：** 手机框宽 320px、最小高 610px、2px 边框、22px 圆角；没有壳内 14px 内边距。顶部另有 24px 状态栏，正文 `.appbody` 只写 `flex:1;overflow-y:auto`，未给正文明确限高。

**F：** 同样的 320/610/2/22 基线，壳内 padding 14px、顶部缺口；正文 `max-height:640px;min-height:0`，并对小画布卡片/按钮收敛内边距。

**影响：** T 正文可能随内容增长而拉长手机框，由外层面板滚动承载；F 更明确把长内容留在手机正文内。具体高度和底栏位置待实测。不能把最终版正文宽度与试跑版直接当作相同：F 的壳内边距会减少实际内容宽度。

**候选：** 分别说明设备框、内容区、顶部/底部固定区和滚动区尺寸；验收长内容及矮视口。现有 ui §7.4 有壳尺寸，但内容区高度/可达性值得补齐。证据 S/R：T 50～62、1848～1854；F 132～152。

### D03 说明区存在重复嵌套滚动

**T：** 移动 `.inspector` 自身 `max-height:calc(100vh - 24px);overflow:auto`，内部 `.component-inspector-body` 又 `max-height:640px;overflow:auto`。两个祖孙容器都可能滚动；选择器未单独设置 sticky。窄屏取消外层限高，但内部 640px 限高仍在。

**F：** 双栏下整条 `.rv-side` 吸顶并独立滚动，组件选择器在这条滚动容器内吸顶；单栏时取消独立滚动。

**可复用：** 明确谁承接说明正文滚动，避免“侧栏一根、正文又一根”。选择器应始终易达；切到单栏后还原正常页面流。ui §8.4 已有意图，但“全界面只保留页面级滚动条”与说明栏例外需要统一。证据 S/R：T 42、403、470～484；F 72～126、740～758。对应 CND-02。

### D04 响应式应看画布实际空间

**T：** CSS 只有 `@media`，以窗口 1000px / 700px 判定，包含业务分栏、后台菜单与阅读器调整。

**F：** 评审外壳、PC 内容、后台画布使用 6 处 `@container`；另保留部分页面级 `@media`。桌面画布宽度由 `measuredCanvasW()` / `syncDeskWidth()` 读取并在窗口 resize 后更新。

**可复用：** 业务布局按画布/容器可用宽度变化；外层模态边距可按视口变化。宽度标注应测量，不把目标尺寸写成实际尺寸。现有 ui §7.4 已要求容器查询，宜增加可观察检查，而非重复原则。

**保留问题：** F 只有 window resize 和渲染后测量，没有 `ResizeObserver`；容器因侧栏/嵌入区域改变而窗口不变时，标注可能过时。应允许能力等价方案，不强制具体 API。证据 S/R：T 470～505；F 419～431、668～676、5720～5744、初始化 resize 监听。

### D05 手机业务弹层的定位宿主不明确

**T：** `.app-mask` 为 `position:absolute;inset:0`，`phoneShell()` 把弹层装入 `.appbody`，但 `.phone` / `.appbody` 未建立定位上下文。移动双栏时更外层 `.canvas-panel` 是 sticky 定位元素。

**F：** `.phone` 明确 `position:relative`；PC `.desk` 也为购买面板建立定位上下文。业务面板相对设备画布，评审图示/阅读器则相对评审视口。

**影响：** T 遮罩有覆盖到手机框外/随外层布局改变范围的风险；这是定位规则推导，未实测像素。**候选：** 明确“业务弹层与评审弹层分别挂在哪个宿主”，测试移动、PC、单栏三种布局。现有 PAT 弹层与运行时规则可补此边界。证据 S/R：T 50、58、215、1848～1856、1979；F 132～137、688～692。对应 CND-04。

## 3. 组件外观、排版与评审阅读

### D06 控件热区：不能用缩小按钮来凑一行

**T：** 手机排序按钮 min-height 30px；顶栏图标 36×36；弹层关闭 34×34；协议勾选行 min-height 34px；广告箭头 28×24。

**F：** 用 `.phone` 作用域约束次级按钮、关闭按钮及 `[role=button]`；轮播箭头 44×44、缩略图 46×44、问号图标视觉 16px 但热区 44px。排序间距单独收为 4px。

**可复用：** 区分视觉图标与真实点击区域；主按钮、次级按钮、弹层内按钮、整行选择都要纳入检查。这些要求 ui §7.3 已覆盖；T 属于源码层面的执行偏差，具体实际热区还需计算样式和点击验证。不要由此声称 F 全部控件已达标。证据 S：T 55、66、82、220、234；F 175～202、307～308、705～715。对应 CND-01/09。

### D07 说明表格字号、列宽与分行不同

**T：** 组件表格 11px、固定布局、4×5px 内边距；说明正文 12px。Markdown `breaks:false`，普通单换行会按软换行处理。

**F：** 说明正文 13px、表格 12px；Markdown 表格单元格默认 min-width 60px、5×6px 内边距，允许表头换行；渲染器把段落行用 `<br>` 连接。组件第 1 节按标签分行。

**可复用：** 条目一行一点；宽表不靠持续缩小文字适配；先给说明足够宽度，再考虑局部滚动。当前 ui §7.2、reader §19.3 已有字号/硬换行意图。**不能全盘复制 F**：它后面把 `.md-tbl-wrap` 的 `overflow-x` 覆盖成 `visible`，窄阅读区反而可能被 min-width 宽表撑开；需保留局部滚动兜底。证据 S/R：T 403～411、457～461、2922～2927；F 754～769、859～867。对应 CND-08。

### D08 彩色模拟封面与灰度占位

**T：** 商品/广告使用 6 组彩色渐变封面，首页还带“精选推荐”等模拟营销文案。

**F：** 多用 `#e4e6e9` / `#eef0f3` 等灰色块，以商品图/视频、文件名等标识素材角色。

**可复用：** 低保真阶段优先表达布局、信息与交互；素材占位不应被误认成已定稿视觉。是否允许强调色/彩色参考图，交给项目目标；不建议把“所有图片必须灰块”设成绝对要求。现有 ui §7 的令牌已基本足够，建议补素材例外范围。证据 S：T 90～101、1867～1869；F 1489～1490、1759～1793。

### D09 描边应避免被滚动容器裁切

**T：** `.outlined` 使用 `outline-offset:2px`，向元素外侧绘制。

**F：** 选中轮廓向内 `outline-offset:-2px`，编号标签为不接收指针的伪元素。

**可复用：** 标注开启前后，业务元素坐标/尺寸不变；贴边组件也能识别。不能只把 -2px 抄成通用答案：向内描边可能覆盖内容边缘，F 的外置编号仍可能被裁。可以用独立覆盖层，保留选择器中的编号作补充。现有 ui §8.6 已规定不改布局，补“裁切/密集内容”验收即可。证据 S/R：T 467、3144～3149；F 717～731。

### D10 注释归属与真实业务提示要分开

**T：** 顶部状态区有注册的页面说明；画布中仍存在“固定 1”“服务端鉴权”“演示账号”等说明；没有与 F 对等的注释按组件收集函数。

**F：** `collectReviewNotes()` 移出显式评审注释与 `.hint`，分发到页面状态或所选组件说明；对业务提示用 `.keep-note` 保留。

**可复用：** 通过明确语义标记区分评审注释、业务提示、字段帮助；不要只按 CSS 类名或正则猜测。F 已为计数新建 `.gd-count` / `.adm-meta` 以避免被收集器误移出，说明自动猜测本身有副作用。现有 ui §8.7 可澄清显式归属优先，不能把所有 hint 都视作非业务内容。证据 S：T 1967、1974、2798；F 514～521、5778～5827。对应 CND-08。

## 4. 交互逻辑与数据上下文

### D11 评审控件不应导致业务画布重建

**T：** 组件下拉 change、描边开关、打开/关闭图示与阅读器均调用 `render()`；该函数直接替换 `#app.innerHTML`。只尝试按元素 ID 恢复焦点与一个光标位置，没有统一保存业务滚动容器的位置。

**F：** `pickComp()` 只更新选择、描边和组件文档；描边开关只改 class；阅读器/图示显示独立的预置层，不调用 `renderAll()`。

**影响：** T 的局部选择可能令业务 DOM、滚动位置及未进模型的输入丢失；焦点恢复不等于状态完整恢复。尚未实际点击，故不声称每个场景必然丢失。

**可复用：** 验收“打开工具→操作→关闭”前后的业务快照一致性；不限定框架，避免不必要的业务重渲染。ui §8.5/§8.9 和 reader §19.6 已要求隔离，但没有明确覆盖这条实际重建路径。对应 CND-03。证据 S/R：T 2970～3012、3271～3275、3529～3532、3182～3242；F 5923～5934、7755～7773、7790～7846、7888～7893。

### D12 二次确认有 UI，但确认动作未接通

**T：** `openConfirm()` 为确认按钮绑定 `handleAction(c.act, c.dataset || {}, true)`。两份内嵌代码范围内，T 仅此一处 `handleAction` 引用，没有定义或赋值；实际分发函数叫 `handleAct()`。

**F：** 确认通过具名引擎与 `adm-confirm-ok` / `adm-confirm-cancel` 分支处理。

**结论：** 在这份自包含 T 中，执行到确认回调会解析到不存在的函数，原动作无法正常重放。此为静态调用路径缺陷；**本轮未点击复现**。语法检查不会发现它。

**可复用：** 二次确认的检查至少包括“确认前不变、取消不变、确认仅一次、对象与参数原样保留”；必须从按钮点击到业务数据结果，不仅检查确认层出现。现有 admin §12.10、runtime §13.3/§13.12 已覆盖语义，优先加执行检查。对应 CND-10。证据 S：[T 确认回调](D:/模型汇总/电子宠物/Steam商城原型交付_V1.4/02_低保真交互原型-试跑版本.html:3174)，T 3569；F 7019～7020。

### D13 找不到记录时不能自动打开第一条

**T：** 通用 `drawerHtml()` 取记录使用 `find(...) || cfg.rows()[0]`；首页广告编辑也有 `find(...) || S.ads[0]`。

**F：** `admDrawer()` 按 ID 查记录，新增模式由 `draftRow()` 显式提供；不存在则显示“记录不可访问”并提供刷新。

**可复用：** 新增与编辑分开，编辑/查看找不到目标不得替换为另一记录。这比“有错误提示”更具体，能防止看错/改错对象。现有 admin §12.6/§12.9 有 ID 和错误态意图，建议补显式禁止。对应 CND-05。证据 S：T 2571～2576、2818～2820；F 5353～5383。

### D14 弹层尺寸与顶部动作已被试跑继承，生命周期仍有差异

**T：** 已是 920px / 86vh 独立后台弹窗，也已把保存放在顶部，不应再列为缺项；正文有 `overscroll-behavior:contain`，未见与 F 对等的祖先滚动锁函数。

**F：** 具备多层 z-index、背景滚动祖先锁定、子层滚动方向判断；提交类成功关闭，失败留在弹窗，查看与就地动作分开。

**可复用：** 复用统一弹层宿主、顶部操作、草稿管理和多层关闭机制；锁背景时不锁死子选择器。现有 admin §12.9/§12.11、runtime §13.8 已覆盖多数规则，应补矩阵验收而非新增相同正文。未保存退出、关闭文字统一性仍由 Q4 决定。证据 S/R：T 374～379、2576、2820；F 486～510、5624～5673、7635～7687。

### D15 操作反馈位置与成功后的状态应一起验收

**T：** 有 body 级固定底部 toast，也有局部 `r.msg` 提示。不能说完全没有反馈；但操作仅显示 toast 不等于数据或流程已推进。

**F：** `admToast()` 工作区提示与说明列 `flash()` 分离；保存规则为成功关闭并写回、失败保留输入和具体原因。

**可复用：** 结果反馈应在操作者当前关注区域可见，配合列表/详情/计数实际更新；避免被遮罩挡住。浮层挂在画布下不一定就被画布边界约束，F 的 fixed 定位仍相对视口，需实际位置检查。现有 ui §7.5、runtime §13.10、admin §12.12 已规定，补可见性与数据结果检查即可。证据 S/R：T 465～466、3000～3002、4617～4624；F 372～377、5935～5956、7635～7687。

### D16 广告看起来可点，不代表有目标行为

**T：** 广告文案“立即查看 ›”渲染在普通 div 中，只给上一张/下一张按钮绑定动作；主广告面未见点击目标动作。它的组件实例差异还声明“仅手动切换，不自动播放”。

**F：** 整图为具名按钮，读取目标广告 ID；多图才有箭头/指示点，并有自动轮播与暂停处理。

**可复用：** 视觉暗示与可操作能力一致；若按 PRD 声明广告可跳转，就应有有效目标、失效目标和单/多图分支。**自动播放不是本轮可直接推广的通用要求**：先查 PRD 与组件契约，不能只因 F 有就强制所有广告自动播。证据 S：T 1867～1869、3585～3590及内嵌实例 diff；F 1501～1527、7703～7715。对应 CND-10/11。

### D17 配置型控件与跨页面数据需用同一事实驱动

**T：** 首页广告有配置/启停数据，但整体模型比 F 更简化；首页配置主要是广告逐行编辑与上/下移。

**F：** 素材增删、商品搜索选择、拖拽、图片预览更完整；搜索推荐配置写回后前台读取同一配置；赠送队列引用订单对象，补发通过订单号同步码与交付状态。

**可复用：** 后台可配内容应能在关联前台看到结果；不要分别维护两份“演示上看起来差不多”的数据。预览/排序按稳定 item ID 跟踪，不能只存数组下标。图片上传要验证能打开原生文件选择、预览、保存后重开。**不推广**商城的具体商品字段、条数、供应商流程。现有 core 同源、admin 第16章与运行时草稿已覆盖原则，补 fixture 和跨页回归。证据 S/H：F `admGoodsMediaPreview`、`bindAdmGoodsDnD`、7451～7474；内嵌 CHG-0059、0074、0075、0079、0081。对应 CND-09/11。

## 5. 流程图与离线阅读器

### D18 两版都已是 PlantUML＋内嵌 SVG

T 有 25 张，F 有 35 张；两版实际 PlantUML 围栏均能在 `DIAGRAMS` 找到逐字对应的图源。本轮未发现缺 SVG 的图项。

因此不能说 T 仍用 Mermaid 或缺图示弹层。F 的历史 CHG-0038 是从更早实现迁移至 PlantUML 的记录，T 已继承这一技术路线。reader §18.1 已规定，无需重复增加。

**样式差异：** T `FL-BUY-001` 为 activity＋泳道，447×1019；F 同 ID 使用 `state` 方框编排流程，1203×1309，节点文本包含稳定 `N-BUY-*` 编号和更多分支。T `SEQ-BUY-001` 为 352×433，F 为 859×2120，后者展开更多调用与恢复细节。尺寸大主要反映信息量和布局方式，不能当作字号更大或天然更清晰的证据。

**候选：** 流程图按业务责任、条件分支与追踪粒度选择模板；不要把所有流程强制为某一种 `state` 语法，也不要把更多图/更长图当质量指标。对应 CND-06。证据 S：两版 `DIAGRAMS`；F 内嵌 CHG-0038 为 H。

### D19 试跑缩放只有状态，没有呈现结果

**T：** 缩放下拉更新 `RV.diagramZoom`，`renderDiagram()` 把它写入 `style="--dgzoom:..."`；全文件没有 `var(--dgzoom)` 消费，也没有将该值应用至 SVG 宽度、transform 或其他缩放样式的逻辑。CSS 仅 `max-width:none;height:auto`。

**F：** `applyDgmZoom()` 计算比例并写 SVG width；默认 fit，不放大窄图；比例低于 0.55 时回到 100% 并允许横向滚动。

**结论：** T 从源码可确认没有把用户所选缩放比例应用到图形；浏览器视觉效果未复现。F 的处理可作参考，但 0.55 不是通用可读阈值。两版 SVG 实际文本多为 11～14px：原文 12px 缩到 55% 只约 6.6px，因此“有 fit 兜底”仍不等于所有中等宽图可读。

**候选：** 验收 SVG 的实际显示宽度随档位变化；结合文字可读性提供 100%/拆图/局部滚动，而不只检查下拉选项。reader §18.5 已有原则，补行为和尺寸证据。对应 CND-06/10。证据 S：[T 图示渲染](D:/模型汇总/电子宠物/Steam商城原型交付_V1.4/02_低保真交互原型-试跑版本.html:3250)、T 3338～3342；[F 缩放函数](D:/模型汇总/CDK商城/Steam商城原型交付_V1.0/02_低保真交互原型-最终版本.html:7741)。

### D20 流程压缩不能丢掉恢复条件和分支语义

T 的购买图把“未实名/未成年/核验失败”合在一个动作出口；F 把平台实名、停止购买、回查、原操作恢复等节点展开。F 的接口时序也更详细。

**可复用：** 允许概览图简化，但重要守卫、未知结果、人工/系统责任与回路必须能在详细图/表中追踪。不是要求每个项目都画 35 张图；应按独立流程和风险边界拆图，并确认概览与详情都指向同一模型。现有 workflow 状态建模、reader §18.2/18.3、deliverables-business 流程/时序章节已有约束，补覆盖矩阵与交叉引用即可。证据 S：两版 `FL-BUY-001` / `SEQ-BUY-001` 图源。

### D21 阅读器从三栏改为两栏，给正文更多空间

**T：** 文档列表 230px＋目录 190px＋正文，阅读器最大宽 1280px。窗口≤1000px 时目录直接隐藏，未见替代目录控件。

**F：** 列表 250px＋正文，目录放在正文上方标签条；窄屏列表切下拉。目录局部滚动/限高，正文拥有更多宽度。

**可复用：** 尽量保证正文、宽表的阅读空间；窄屏应折叠或替换目录，不能静默失去定位能力。**两栏＋顶部目录可作推荐实现**，现有 reader §19.2 允许目录在左或顶部，不宜仅凭单个样例删除全部其他布局。证据 S/R：T 439～484、3200～3220；F 826～849、1050～1075。对应 CND-08。

### D22 工具层上下文恢复需要完整闭环

T 的阅读器关闭会再次整页重绘；文档切换直接走 `openReader()` 并清空历史，历史栈虽定义了“返回”函数但未见对应文内 MD 跳转入栈路径。F 保留文档滚动映射和目录定位，但关闭阅读器仅把焦点放到第一个入口按钮，关闭图示只移除 class。

**可复用：** 分别约定新文档切换、文内跨文档跳转、历史返回和关闭后的恢复；恢复到真实触发入口，不统一跳第一按钮。目录跳转只滚正文，不拖动背景。reader §19.4/19.6 已要求；应按矩阵验证，两份实现都不能直接标为完整通过。证据 S/R：T 3182～3220、3351～3354、4591～4602；F 7790～7846、7771～7773。对应 CND-03/04。

## 6. 组件文档、样例覆盖与可维护性

### D23 共享复用合理，但完整十节不等于足够具体

T 用 79 个定义支撑 141 个注册实例，说明区同时展示共享定义、模式、实例差异；F 把更多页面实例写成完整十节，共 192 定义。两种组织都有价值，不能强制所有实例复制完整说明。

静态重复统计：T 第5节有 37 个定义正文完全相同，第8节有 31 个，第10节有 49 个；F 相同节的最大重复数分别为 1、2、2。**重复并非自动错误**，但需要检查通用文字是否替代了这个组件特有的来源、禁用原因、取消、成功/失败和验收行为。

可复用方案：完整共享定义＋实例覆盖项＋说明区解析合成，按具体实例展示适用差异；禁止只用“见共享定义”留空。T 当前显式展示实例 diff 是值得保留的做法。ui §9.5、core 同源和 docs-ui 组件十节规则可增加实例完整性检查，不以文档字数、定义数为门槛。对应 CND-07。

### D24 当前页全量组件与“当前已渲染组件”不是一回事

**T：** 选择器取该页注册的全部实例，能提示所选组件在当前状态未展示。

**F：** 选择器扫描当前画布的 `data-component`，只列当前 DOM 实例。文档渲染支持“当前未展示”，但仅当前 DOM 生成的下拉无法主动选到未渲染实例，需切状态或保留原选择。

**可复用：** 保留 T 的页级注册表取数方式，结合 F 的紧凑下拉和局部更新；可标注“当前状态未展示”，而不是把定义从入口中消失。现有 ui §8.5 已有未展示提示，候选条款明确列表范围。证据 S：T 2921、3109～3119；F 5867～5919。对应 CND-07。

### D25 演示数据需要覆盖可操作分支

F 的历史修改记录包含“初始热门商品已配满，新增实际上无货可选”“隐藏 file input 没有触发入口”“保存仅显示提示不写回”等问题；后来分别留出可添加商品、接通原生上传、补配置写回。T 的部分操作也采用简化数据/静态分支。

**可复用：** 固定 fixture 覆盖有效/失效目标、可新增/已配满、记录删除、失败/未知、长文本、多个素材和跨页同步；这些用例数据随参考实现维护。**不得继承历史 CHK 通过结论**。现有 quality/evidence、运行时与同源要求可挂接具体回归样例。对应 CND-09/11。证据 H：F 内嵌 00/08 的 CHG-0059、0068、0077；本轮只静态阅读。

### D26 变更记录很有价值，但需要区分最新结果与历史过程

F 的内嵌 00/08 保留了多轮具体问题和修复，能还原人工调整动机。例如说明栏曾在“独立滚动→取消→再独立滚动”之间迭代，组件选择器也从列表到网格再到下拉。T 的当前实现则已吸收其中部分结果。

**可复用：** 从“最后确认的行为＋当前实现”提炼规则；历史相反方案只保留在变更日志，不一起进入规范。记录规则/PRD/人工决策基线与产物哈希，用同一 PRD 比较迭代前后。对应 CND-12。

## 8. 最终版也不宜照搬的实现细节

1. **选择器仅扫当前 DOM**，弱化未展示组件的可发现性，见 D24。
2. **宽表 `overflow-x:visible` 覆盖局部滚动**，窄屏完整性需要复核，见 D07。
3. **图示 0.55 阈值不是字号保证**，fit 档位下部分图文字仍可能过小，见 D19。
4. **多层 Esc 的关闭范围不完整。** 顶部优先判断确认层后，普通后台分支直接清空 `rt.drawer`；没有按 `regOpen` / `pickOpen` / `srPickOpen` 等所有子层逐层关闭。具体场景需实测，不宜当作完整层栈参考。源码 F 6562～6570。
5. **焦点恢复不完整**：图示关闭未显式恢复入口，阅读器统一恢复第一入口；源码 F 7771～7773、7842～7846。
6. **旧页状态标注不齐。** F 保留退款、支付核查、客服配置、基础统计页面；只有部分页注册 note 清楚标出“侧栏已移除/页库保留”。菜单消失不等于已从交付范围移除。源码 F 5558～5564，历史 CHG-0086～0089。
7. **部分呈现仍较小**：F 媒体占位、缩略图等仍用 11px；不能宣称最终版全站正文/辅助文字都满足当前 12～13px 基线。

以上是维护标准时需要避开的参考实现局限，不是对用户已认可结果的重新否决；本轮没有改动任一原型。

## 9. 建议的规范落地方式

优先处理 **CND-03、04、05、06、07、10**：都能对应本轮明确的源码路径和可观察行为。其余按用户确认收敛默认值和补样例。

推荐新增体量集中在：一份几何/滚动矩阵、一份工具状态隔离矩阵、一份动作闭环矩阵，以及按需加载的参考实现。活动规范只修订原归口条款并链接矩阵，避免本报告、十节示例、验收表再各复制一遍权威要求。

# 第四批：文档、评审工具与交付一致性

沿用[基线](01_补充审查基线与入口.json)；T/F 为两份 HTML 的行号。[交付物局部核对](10_交付物局部核对.json)保存内嵌 JSON 元数据、有限短证据、外部文件哈希与差异位置，不输出内嵌全文。本批 7 项观察包括正向差异、风险和执行缺口，并非 7 个已实测缺陷。

## D01 字节同源要核对最终文件，不能凭“由构建生成”推断

- **差异**：T 的 9 份主交付 MD 与同目录外部文件一致；附加 PRD 的同名外部文件未找到，不能据此判断 PRD 内容错误。F 的 9 份主 MD 中 8 份与外部文件不一致，只有 06 相同。比较已排除 BOM 与 CRLF/LF，不是换行误报。
- **证据**：T:522 的 DOCS；F:7995 的 DOCS；10 JSON 的 documents 下有外部绝对路径、原字节 SHA-256、规范化比较结果。F 的 00 首处差异在内嵌第 40 行，外部增加了流程/异常/上游接口/测试数；01 首处在第 100 行，外部多了上游发货核查/补录能力。这里只记录当前磁盘状态，不推断当年文件形成顺序。
- **归因与处理**：已有 [core §3.4](../../../standards/core.md#s-3)、[reader §19.7](../../../standards/diagrams-and-reader.md#s-19) 同源要求。T 在此项更好；F 不可整体晋级为黄金样例。先确定交付批次和 MD 权威版本，再重建；不能擅自把外部新增供应商能力扩成所有项目需求。
- **验收**：最终交付的 MD→内嵌正文→下载内容逐份同源核对；必要规范化须固定方法且保留原字节哈希；改后重新记录最终文件哈希。候选 K07。

## D02 字节一致也可能把错误范围同步到所有文件

- **差异**：T 的组件说明写有“历史不纳入首期”，运行模型也缺搜索历史；这与当前 client §10.2 的历史管理要求不一致。F 虽有历史功能，内嵌 03 的前段仍存在“当前按未启用处理”的旧表述，同时其他段落描述历史能力。
- **证据**：T:520，COM-CLIENT-C01，内嵌 03 第 84 行；F:7993/7995，COM-CLIENT-C01，内嵌 03 第 105 行；10 JSON 的 search 短证据；功能实现见 A01。文档的旧待确认文字不是本轮用户批准的裁剪。
- **归因与处理**：同源和语义一致是两项检查；不能只重建 HTML 就认为修好。按 core 优先级核实批准的范围，修正 PRD/契约/实现/01/03/07/08 的对应关系；当前源码比较不倒填其历史生成规范版本。
- **验收**：给每项能力核对已批准/待确认/废止状态与真实入口；有文档冲突必须处置，不以“有 TBD”自动覆盖已生效规范。候选 K07。

## D03 组件十节齐全不等于具有可实施的细节

- **差异**：T 79、F 192 个定义均有十节。T 第 5 节最多 37 个定义共用一段通用视觉文字；部分第 7 节只写“随宿主页面 API”。F 多数正文更具体，但第 8/10 节也有重复，且其价格/历史等仍有语义反例。
- **证据**：T:520，COM-CLIENT-C01～C04 的第 5 节；ADM-COMMON-C03 等第 7 节。10 JSON 保存 sample_ids/短证据；原结构清单保留十节与数量统计。
- **边界**：通用令牌复用、后台无业务埋点依据、相同不适用说明可以重复；不能以重复比例、字数或最终版组件更多直接判质量。不同 ID 也可能只是实例拆分。
- **归因与处理**：按 [deliverables-ui §22](../../../standards/deliverables-ui.md#s-22)检查组件自己的字段生产/消费、条件、成功失败与用例。复用模式后应补实例差异；确实无接口/埋点要给依据，不能用泛话代替必需契约。
- **验收**：优先抽查搜索历史、规格选择、退款提交、角色保存等已发现矛盾的组件；逐项对照真实入口及可判定结果，不追求扩写篇幅。候选 K07。

## D04 选择组件说明应保留业务 DOM 与输入现场

- **差异**：T 组件选择触发整页 render，替换 app.innerHTML；虽保存 focusId 和 selectionStart，但没有完整选择区间/方向、业务容器滚动等快照。F pickComp 只更新选中、描边与说明区，是更窄的更新路径。
- **证据**：T:3363～3365、3033～3049、3065～3071；F:5928～5933。T 有部分焦点恢复，不能写成“完全没有恢复”；也不能由源码推断其输入法或滚动已经实机失败。
- **归因与处理**：属于 [STD-RV-001](../../../standards/ui-and-components.md#s-8) 与 runtime §13.5 的执行复核，不重做此前外壳布局/滚动条主题。局部更新可降低扰动，等价实现仍以不改业务现场验收。
- **验收**：选择一段文字、输入法组合、编辑未提交、打开业务子层、业务画布滚至中部，切换组件/描边后逐项比较。真实浏览器尚未执行。候选 K03、K07。

## D05 阅读器需同时验证切换、返回、下载与关闭

- **差异**：T 记录 readerHist、readerScrollMap，有上一文档/目录/下载入口；F openDoc 保存阅读位置、buildToc 只滚正文容器，关闭后聚焦 readerEntry 的首按钮。两者都有能力骨架，但不等于恢复了原触发入口与完整业务快照。
- **证据**：T:3251～3267、3277～3289、3444～3460、4735～4754、4785～4788；F:7790～7808、7812～7846、7848～7856。T 下载和 F 下载均从当前 DOCS 的原 md 建 Blob，源内容是否正确另见 D01。
- **归因与处理**：[reader §19.4～19.6](../../../standards/diagrams-and-reader.md#s-19)已有完整要求。不能将“恢复到任意入口”当成“回到原触发按钮”。新文档从开头与返回恢复位置要区分，不自动套同一缓存策略。
- **验收**：从不同文档入口打开，切换 A→B→返回 A、点击目录/文内 MD 链接、下载、关闭；核对文档 ID/标题/目录/文件名/内容与位置、业务状态不变及焦点回原入口。候选 K03、K07。

## D06 图源、离线 SVG 与查看入口需要连成一条链

- **差异**：T 28、F 35 张图均有注册元数据；T renderDoc 按 trim 后图源查 DIAGRAMS，未找到时明确提示缺 SVG；F Markdown 围栏调用 renderDiagram，并保留图源入口。数量减少可能来自流程合并，也可能是缺项，不能单以 28<35 判不合格。
- **证据**：T:3200～3206、3291～3299、3301～3325；F:1205～1207、7717～7771；原清单 diagram_entries 与 10 JSON 的 plantuml_fence_mapping。当前 T 内嵌 MD 的 28 个 PlantUML 围栏均可精确匹配注册图源，证明注册链，尚不证明图形可读。
- **归因与处理**：[diagrams §18、reader §19](../../../standards/diagrams-and-reader.md) 已要求图 ID/来源、离线资源与可读查看。按职责比较主链/异常分支，不要求照搬最终版图数量或尺寸。
- **验收**：入口→正确图 ID/SVG→缩放/移动→关闭恢复；断网检查图不依赖远程渲染；核对节点文字、箭头和业务状态与 04/05 一致。图源精确映射、SVG 存在、浏览器可读分别记录。候选 K07。

## D07 复制反馈必须取决于能力结果

- **差异**：T Clipboard Promise 有成功/失败分支，但兼容路径忽略 execCommand 的 false 返回，仍提示复制成功。F writeText 的拒绝被空 catch 吞掉，随后同步提示已复制；没有可用 Clipboard 时也可能走同样成功反馈。
- **证据**：T:4275～4289；F:6785～6790。PROBE-14 让原兼容 API 返回 false，收到“已复制到剪贴板”。F 为源码风险，未做浏览器权限拒绝复现。
- **归因与处理**：[STD-ACT-001](../../../standards/runtime-and-build.md#s-13) 已要求动作闭环与可观察结果。应在实际 fulfilled/明确 true 后反馈；失败或不支持保留可选择文本与手动办法。系统剪贴板、下载、外部唤起不能仅因点击发生就标成功。
- **验收**：支持且成功、权限拒绝、API 不存在、兼容返回 false、同步异常；点击 B 的复制只能取得 B。候选 K05、K07。

本批不把原型内嵌 08 自述的“浏览器探针/通过/未执行”计入本轮执行记录；它们只是历史交付内容。本轮浏览器验证为未执行，外部文件只做哈希与有限差异定位。

# 第一批：客户端、购买与交易细节

基线、源文件绝对路径与 SHA-256 见 [审查基线](01_补充审查基线与入口.json)。下文 T 为试跑 3.0，F 为最终版；`T:行号`/`F:行号`定位原文件，不复制原型或内嵌文档。分类依据当前提交 cd12fa6 的活动规范，不把过去试跑 2.0 的结论继承成本次证据。原七主题不重复审查。局部复核只执行原函数/原语句和隔离夹具，不是浏览器验收。

## A01 搜索历史是完整能力，不能只提供热门词

- **两版差异**：T 的搜索模型仅有 keyword/sort/results/end/page，搜索首页只绘制发现词和热门商品；提交处理也未写历史。F 有提交去空白、去重置顶、管理态、单条删除、清空和删空退出管理。
- **证据**：T:1528、1922、3657；F:1417、1428、6650、6686、6694、6704；PROBE-03 实测原历史辅助函数将 `[A,B]` 更新为 `[B,A]`。
- **归因**：既有要求未落实；不是新增搜索历史需求。依据 [client §10.2](../../../standards/profiles/client.md#s-10) 与 [内容模式](../../patterns/content-and-navigation.md)。F 的 10 条/30 字仅为该实现参数，不推广为统一数值。
- **处理与验收**：修试跑实现；提交 A、B、A，再单删/清空，新开搜索与返回搜索分别检查。需明确历史归属账号/设备及存储边界，不能把热门词冒充用户历史。

## A02 两版都存在“零结果回填演示商品”的反例

- **两版差异**：T 的 doSearch 得到空集合后仍进入 RESULTS，渲染器把空 results 替换为“星海”商品；F 的渲染器在 hits 为空时取 GOODS 的前几个示例。两者都可能显示与提交词不匹配的商品。
- **证据**：T:1935、1936、3666、3669；F:1721、1737。PROBE-01/02 用无匹配关键词隔离执行原渲染函数，均得到演示商品。
- **归因**：两版共同实现缺陷；当前 [内容模式](../../patterns/content-and-navigation.md) 已明确“无匹配不补演示商品”，不应再新建同义规则。
- **处理与验收**：空集合、字段缺失、请求未完成和明确失败分别建模；仅合法空集合显示 EMPTY。请求未完成不能回退样例，失败重试沿用已提交条件。候选执行细化 K01。

## A03 推荐商品需要过滤真实可售状态

- **两版差异**：T 的 hotProducts 只按固定 ID 取商品并排除找不到的对象，没有按商品可售状态过滤；F 对推荐启用状态、商品存在性、在售状态与展示数量逐项过滤。
- **证据**：T:777、778、1624、1627；F:1398、1403、1405、1409。这里比较的是数据读取链，不是推荐顺序样式。
- **归因**：配置消费与失效对象处理不足，既有 [数据模式](../../patterns/data-and-transactions.md) 与 [admin §16](../../../standards/profiles/admin.md#s-16) 已覆盖基本原则。
- **处理与验收**：停用推荐、下架商品、删除引用和合法清空后检查 APP/WEB；合法空配置不回退默认推荐。项目决定实际展示上限。

## A04 媒体缩略入口需要对应真实素材与当前对象

- **两版差异**：T 的详情固定绘制三个缩略占位，无对应媒体切换入口；F 的 mediaItems/mediaCarousel 按后台媒体构造序列，并有 media-go/prev/next 行为与换商品归零。
- **证据**：T:1951、2276；F:1362、1759、1769、5577、6742。不根据图标或占位数量断言上传/视频播放已经实现。
- **归因**：可操作性与内容模型的执行缺口；[表单模式](../../patterns/forms-and-layers.md) 已要求稳定媒体 ID、重排/删除后的预览对应关系。
- **处理与验收**：0/1/多项媒体、删除当前项、重排、切换商品、图片与视频类型分别检查。视频是否需要由 PRD/已批准项目契约决定，不能普遍强制新增视频能力。

## A05 最终版规格价格实现不能作为黄金规则

- **两版差异**：T 建单 amount 取当前规格 price；F 后台规格存在独立 price，但购买面板第二规格仍按基础价加固定 40/60 计算。F 的数据联动展示不等于配置消费完整。
- **证据**：T:1545、1668、1675；F:1891、1915、3313。PROBE-05 给第二规格配置 260，原面板价格表达式返回 140。
- **归因**：最终版反例；已有同源与规格金额要求足够判定缺陷，不能将固定加价归纳成通用业务规则。
- **处理与验收**：配置规格价→详情→购买→新订单逐项比较，使用非等差价格并选择第二条记录；核对商品 ID 与规格所属商品一致。候选细化 K02。

## A06 同商品重开购买面板与换对象须分别定义

- **两版差异**：T 每次 beginBuy 重建 S.buy；F 的 open-panel/close-panel 只改变面板开关，原规格、渠道、协议等会继续留在会话中。F 的跨商品隔离仍不能仅凭“同商品保留”推定成立。
- **证据**：T:1633、1637、3761、3766；F:6719、6724、6735、6740、5578。PROBE-04 对同一商品重开后，规格/链接/渠道/协议被重置。
- **归因**：本商城已有 [项目契约 §3](../../../reference/projects/steam-store.md) 明确同商品保留，因此 T 是项目执行偏差；其他业务的保留策略仍须登记，不普遍强制所有草稿永久保留。
- **处理与验收**：同商品关闭重开、切商品、切账号、取消认证返回分别检查；保留用户输入与重新核验资格分开。候选细化 K03。

## A07 显式失效订单 ID 不应换成其他订单

- **两版差异**：T 的结算、结果、详情多处使用“按 ID 找→取其他待付/已付订单→取第一条”的回退；F 部分订单入口通过 data-order/resumeOrder/detailOrder 传递对象，但客服仍使用 MOCK_ORDER。不能按最终版按钮表现推断对象身份已全链正确。
- **证据**：T:2053、2087、2097、2153、2309；F:6619、6764、2490。PROBE-11 请求 MISSING-B，T 的原详情选择语句返回 A。
- **归因**：既有 [admin §12.6](../../../standards/profiles/admin.md#s-12) 与 [STD-ACT-001](../../../standards/runtime-and-build.md#s-13) 的稳定对象/失效目标要求未执行；适用客户端的同样原则不得遗漏。
- **处理与验收**：必须用 A/B 两对象及失效 B，从列表、支付返回、旧单恢复、客服分别核对；无权限与不存在显示明确结果，不能兜底第一条。候选细化 K02/K03。

## A08 历史订单展示应读取成交快照

- **两版差异**：T 金额保存在订单中，但 orderProduct/orderSpec 每次读取当前商品/规格，所以修改目录名称会改变历史订单展示。F 存在 MOCK_ORDER 和客户端/后台多套记录，不能据其固定展示推断真实快照已连通。
- **证据**：T:1550、1551、1669、2164；F:1370、1379、3113。PROBE-12 修改当前目录后，原 orderProduct/orderSpec 从 OLD/OLD-SPEC 变为 NEW/NEW-SPEC。
- **归因**：已有 [数据模式](../../patterns/data-and-transactions.md) 的历史快照要求未落实。
- **处理与验收**：冻结名称、规格描述、金额、交付资料、协议版本的成交快照；目录改名/删规格不追溯改旧单。库存或当前可售性可另行实时查询，不混写历史事实。候选细化 K02。

## A09 支付确认与交付结果在最终版也未完全分离

- **两版差异**：T 的 markPaid 对 CODE 先 ISSUING，再由回调改 DELIVERED；F 的 resolvePayQuery 正常分支设 orderPaid 后直接进入 DELIVERED。两者都是模拟，不代表真实供应商已交付；F 的捷径不得推广。
- **证据**：T:1692、1697、1703、1742；F:6994、7008、7009。T 的定时回调还需检查失效上下文，见第三批。
- **归因**：已有 [数据模式](../../patterns/data-and-transactions.md) 和 [商城状态契约 §9.1](../../../reference/projects/steam-store.md) 已区分支付/交付/售后；不需要新增同义状态规范。
- **处理与验收**：付成功但发码中、发码失败、赠送待处理、结果未知独立覆盖；两端分别走入口，不能以一个 DELIVERED 预设替代支付与交付的实际动作。候选细化 K05。

## A10 返回路径不等于业务现场恢复

- **两版差异**：T 的 pageHistory 只保存 pageId/state/end，navigate 还把业务正文 scrollTop 归零；F 的 RV.from 只保存来源页和状态，默认搜索入口主动清空关键词。两版的来源记录都不足以单独证明搜索条件、页码和滚动恢复。
- **证据**：T:3003、3007、3017、3019；F:5574、5581、6634。属于源码可见的恢复字段缺口，真实浏览器回退位置仍未验证。
- **归因**：[内容模式](../../patterns/content-and-navigation.md) 已区分新开与返回；已知原则的实现与验收缺口。
- **处理与验收**：搜索中段→商品 B→返回，核对已提交条件/结果集/页码/滚动/焦点；新开搜索保持空输入。保存的上下文绑定端、账号和对象，不能恢复到不兼容场景。候选细化 K03。

## 本批结论

10 项中包括试跑版执行缺口、两版共同反例、最终版反例和项目特定保留策略；不能归纳为“最终版十项都更好”。现有规范已覆盖多数原则，补充价值在可执行断言、具体字段和反例夹具。没有改动两份 HTML，也没有给任何浏览器场景填写通过。

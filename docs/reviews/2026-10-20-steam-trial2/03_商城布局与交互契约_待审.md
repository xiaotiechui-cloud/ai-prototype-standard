# Steam 商城：PC 详情与购买参考契约（候选）

> 后续状态：本项目设计契约已按用户本轮批准整理至[商城项目契约](../../../reference/projects/steam-store.md)，本文件保留为候选来源。设计批准不等于浏览器验收或真实服务通过。

用途：将用户认可原型中的细节缩成可执行的项目输入；供后续生成 AI 按能力读取。不是活动规范，不是已通过浏览器回归的黄金实现。参考产物与差异见 [详细分析](01_详细差异分析.md)。

## 1. 范围与优先级

- 规则基线：V3.0 / modular-1 / draft-20261020-q1-q7；参考仓库 commit `fbc394d02e9e5fa07bf0511be284e7155f31f6f8`。
- 本项目认可参考：最终版 SHA-256 `04bf9e76f416833e1ac84e97408b81cbceb043bb44dca4a0529f3c80f418765f`；用户明确中文主显示、灰度线框且保留交互。
- 原 PRD 为试跑 HTML 内嵌 V1.4 待评审稿；其自报源文件哈希未独立验证。人工确认布局可补足 PRD 呈现细节，业务补充与未接入能力须明确登记。
- 本契约优先固定用户认可的业务结构和返回行为，不照抄参考源码中的模拟捷径、占位订单数据、评审文字或“已付款即交付完成”文案。资金、权限与资格仍以 PRD 和可信服务端结果为准。

## 2. PC 商品详情布局

```text
业务画布宿主（明确定位上下文）
├─ 容器框/必要平台信息（不得冒充实测宽度）
├─ 业务正文滚动区
│  ├─ 站点导航：商城 / 搜索商品 / 我的
│  ├─ 业务标题行：返回 + 商品详情
│  └─ 详情两栏
│     ├─ 左：媒体主区 + 实际媒体缩略入口
│     │      游戏介绍（非空）
│     │      硬件配置（项目补充；至少一组非空）
│     │      商品须知（非空；长文展开/收起）
│     └─ 右：名称/英文名（有资料时）/售价/类型/可售状态
│            独立购买卡：金额 + 可售/处理中/不可售操作
└─ 独立业务 overlay 宿主（不塞进正文 main 内容）
```

参考布局值：内容最大宽约1200～1280px，默认内边距24px；宽屏两栏约1.15:1，媒体占位高280px；多项缩略参考72×46px，购买主面板约600px、扫码层约420px。以上固定本项目参考意图，不是本轮实测尺寸，也不是所有详情页的强制值。窄容器按已登记断点降栏，保留来源、顺序与主操作。

| 分区 | 数据与空值 | 交互不变量 |
| --- | --- | --- |
| 媒体 | 商品媒体稳定 ID、类型、顺序、标识；缺项用合法灰色占位 | 按实际数量生成；一项无多项切换；点击更新主媒体与选中态；帮助/购买不意外改选中项 |
| 游戏介绍 | 后台商品介绍，同移动端数据源；空值不生成整个分组 | 长文可完整到达，不挤占右侧购买卡 |
| 硬件配置 | 最低/推荐分别有来源；空行不出，两组都空则隐藏 | 没有可信数据就不填猜测值；不把模拟搜索当真实抓取 |
| 商品须知 | 与后台同字段；参考摘要前60字，长文可展开 | 展开/收起文案随状态变化；不因切说明组件重置 |
| 购买卡 | 当前商品＋来源平台账号的有效关联订单；未登录不泄露个人订单 | 可售无旧单打开主面板；有效待付/确认中先查询恢复旧单；下架不新购且保留关联订单查看 |
| 返回 | 明确来源页和上下文 | 标题旁返回；恢复来源搜索/筛选/页码/滚动，来源失效有明确可达回退 |

可独立评审的媒体、资料、须知、购买卡、购买面板分别有组件语义与说明，不要求复制最终版 C01～C10 历史编号。

## 3. 购买主面板

主面板在 PC 业务宿主内居中，遮罩恰覆盖业务宿主，不遮住外部评审工具；尺寸依据宿主剩余空间约束，矮视口标题、关闭与主操作可达，长正文独立滚动。禁止用视口 vh 和宿主百分比拼出无校验的抽屉偏移。

内容顺序：

1. 标题“核对购买内容”与关闭。
2. 商品灰色小图/名称/当前版本/当前价格。
3. 版本选择行：名称、选中反馈、价格、适用限制；有批准帮助内容时显示问号。
4. 发货方式与适用地区/限制：由真实商品或规格配置驱动；只有一种时展示，多种才允许选择。
5. 好友链接：仅赠送要求，错误就近提示；支付前可改，支付后锁定。
6. 微信/支付宝选择：保留当前选项；无未批准支付方式或优惠抵扣。
7. 协议真实选择及查看入口，默认不同意，不从“浏览过”推定同意。
8. 校验反馈、金额和“购买并支付 ¥金额”主操作。

同一商品关闭主面板后重开，保留已选版本、方式、链接、支付渠道和协议当前选择；新的商品/账号上下文不能带入上一对象私有资料。保留草稿不等于保留资格通过状态；确认订单的金额和交付资料来自原订单快照，发现变化先提示确认，不静默覆盖。

## 4. 层与取消返回

| 当前界面/入口 | 呈现 | 取消/关闭 | 不允许发生 |
| --- | --- | --- | --- |
| 详情→立即购买 | 购买主面板 | 回详情，按同商品策略保留现场 | 仅弹 toast 或跳错端 |
| 未实名/未成年/核验未知 | 主面板内就近消息；可执行平台承接另作明确入口 | 留在主面板或主动关面板 | 替换成其他端页面；把点击重试当成年成功 |
| 未同意→购买 | 主面板保留，上方购买须知子层 | 只关子层，回主面板原位置 | 关闭父面板、清空规格/链接、建单 |
| 须知→查看协议 | 协议查看层/页面，登记来源父层 | 返回原购买须知/主面板及其滚动 | 仅记“返回商品页”而丢失购买层上下文 |
| 同意并继续 | 关闭须知，记录明确选择，继续核验手机及后续条件 | 失败保留主面板现场 | 跳过手机号直接支付 |
| 版本问号→CDK帮助 | 帮助子层，不选择版本 | 回问号触发位置/父层滚动 | 顺便改变规格或支付方式 |
| 未绑手机 | 主面板消息及平台绑定承接 | 取消/失败/未知留现场不建单；成功返回重查 | 只写 phoneBound=true 冒充真实返回 |
| 确认订单→扫码层 | 独立支付层 | 回确认订单，原订单与状态保留 | 将关闭解释为未付款或取消订单 |

一次 Esc 只处理栈顶，子层关闭不解锁仍有父模态层的背景；焦点限制于当前层、关闭回对应触发入口。纯说明直接关，有脏数据按项目明确策略处理。父层可因模态被遮罩/锁定，但其状态不能被替换或清空。

## 5. 下单与扫码状态转换

```text
购买并支付
→ 必要时登录并取得当前平台账号
→ 实名/成年（未通过、未知即阻断）
→ 购买协议（未同意先须知）
→ 手机绑定（失败/未知阻断）
→ 商品/价格/规格/资料/旧单校验
→ 防重复提交，创建或恢复同一订单
→ WEB确认订单页 + 待扫码支付层【本项目认可路径】
→ 已扫码：确认中（不能再次发起支付）
→ 可信查询结果：未支付 / 确认中 / 异常或未知 / 已支付
→ 已支付：保留订单，另按交付状态展示发码中/已发码/异常/赠送处理中等
```

| 状态 | 可见内容 | 合法动作 / 不变量 |
| --- | --- | --- |
| 待扫码 | 中性灰色二维码占位、订单号、金额、操作提示 | 渠道已在上页选定，扫码层不重复展示/切换渠道；可关闭，关闭不变订单状态 |
| 确认中 | 正在查询支付结果、不要重复支付、订单标识与金额 | 提供重查；若允许关闭则只退视图，重进仍查询该订单 |
| 未支付 | 明确查询结论与可继续条件 | 再发起付款前重验资格和订单可支付性；不同支付尝试先处理旧尝试，不并发新建 |
| 超时/异常/未知/无权限 | 分别明确提示，不推定已付或未付 | 按原因重查/重新登录/返回，保留安全的订单引用；不可放行或复制假码 |
| 支付成功 | 成功文案、订单号、金额、去订单/关闭 | 只表示支付成功；CODE仍可能发码中，GIFT仍可能待处理；不暗示交付已完成 |

页面预设与业务模拟必须共同驱动上述可见结构，只有一套明确的状态映射。若内部拆成 RV.state 与业务支付状态，必须定义同步/隔离规则；不能预设显示成功而订单仍无对应含义。

## 6. 旧单、对象身份与全局外观

- 详情“订单处理中”、列表继续支付、查询结果、扫码关闭重进均按原订单稳定 ID；查询已付进本端结果，未付且合法进本端确认订单，未知保留确认中，已关闭按规则解除标记。
- 未登录、错账号、失效 ID、商品缺失明确提示；不回退第一条订单或其他商品。复制订单号来自当前展示对象；无权限/空码无复制成功动作。
- 来源平台身份与当前查看端分开；切端清掉不兼容的页面/组件/瞬态和迟到回调，不能发生状态已换但画布未更新。
- 业务画面灰度线框；中文主显示，内部状态码稳定；业务区与弹层正文隐藏滑块但保留滚轮、触摸、键盘到全文；说明列按悬停/聚焦显形规则。
- 组件选择/描边/阅读器/图示不改业务输入、稳定对象、父层开闭及滚动。局部更新优先；重建必须验证完整恢复。

## 7. 项目补充与禁止推导

| 人工认可版细节 | 此契约处理 | 尚不能推导 |
| --- | --- | --- |
| 最低/推荐硬件配置 | 作为本项目补充区，来源/空值明确 | 自动真实抓取 Steam、所有商品已有可信配置 |
| 图片/视频共用媒体入口 | 图集属原范围；视频作为单列补充，有批准配置才展示类型占位和交互 | 已有播放源、版权授权、真实转码/播放器能力 |
| 多种发货方式 | 仅真实配置允许多选时呈现，切换更新必填资料/限制 | 所有商品都同时可 CODE/GIFT，或不同能力可互换 |
| CDK帮助及地区说明 | 作为该商品批准内容，关闭不改变选择 | 全部商品仅国区、帮助文字可替代供应商真实限制 |
| 建单直接出码 | 本项目PC路径，按业务守卫与真实能力接入 | 其他项目无需确认订单、真实渠道已支持该方式 |

这份契约提炼的是设计与行为，不能代替真实接口契约、权限、幂等、资金结果、供应商交付与平台适配。作为候选参考不宣称当前 HTML 已能直接上线。

## 8. 交给下一次生成 AI 的要求

先实际读取仓库入口和按需规范，再读取本契约；报告参考哈希、已批准与待确认补充。用一个 CODE、多规格，一个 GIFT、长链接，以及两笔不同订单 A/B 作为最小夹具。先交 PC 详情与购买主/子层关键路径供评审，再补全其他交付；最终10项主交付要求不因此缩减。

验收用 [专项矩阵](04_回归验收矩阵.md)，逐条记录未执行/失败/通过。生成 AI 不能把本文件写的预期、用户最终版中的历史 CHK 或本轮 ISO 函数观察当成本次浏览器证据。

# 页面布局与组件对比

本批只比较可复用的交互/UI原则。最终版 V1.5 与试跑15不是同一页面拆分或同一页面状态分母；最终版结构清单来自试跑14 sidecar，哈希经本轮确认未变。修复后试跑15没有独立浏览器复验，故对它只报告源码/交付声明及本地自测，不声称当前画面与最终版已达成或未达成视觉一致。

## 可观察到的基线

- 试跑15的 UI Profile 标识 `steam-mall-gray-v1`，移动设备框声明320×640、内部业务区288×592、2px `#8d939b`边线、22px圆角；桌面最大内容宽1280，后台侧栏220/64，弹窗宽度档400/600/920。配置和哈希记录在02的 `PROFILE`/`PROFILE_HASH` 与00/09。属于项目实际采用值，不提升为所有项目的固定像素规范。
- 最终版结构统计为49页、185状态、36图、221个组件定义；试跑15为44页、225状态、16图、98定义。差异须看职责映射、同端同状态几何合同与动作结果，不能以数量投票。
- 修复后的08报告在“组件实例归属、弹层宿主、焦点回退、设备业务区几何”等处引用本地自测；首次验收 DEF-010/016 曾指出注册实例与DOM归属不一致、移动购买弹层使用错误宿主并覆盖业务画布。对应规则已经存在于 core3、ui8/15、runtime13、quality29.10/29.11。

## 规范判断

目前没有证据说明需要新增手机外壳、弹窗、输入控件、PC布局或组件十节的通用样式规则。现规范已要求：输入Profile和变体能追溯、实例/DOM同源、宿主几何单独登记、业务弹层相对业务画布定位、焦点进入与恢复、窄矮宿主和长内容实测、组件行为与字段合同可执行。

主要问题是首次生成结果没有遵守这些已有契约，且生成方的40项初始自检未发现25个DEF。可优化之处应落到出门检查的实际断言和覆盖证据：按“端×宿主×组件职责×关键状态”执行代表样本，测DOM归属/计算几何/真实操作结果，不以CSS令牌、ID存在、渲染成功或截图单独判定合格。

## 边界

- 最终版可以作为人工偏好的布局及交互表现样本；它不能覆盖PRD，也不是业务正确性唯一标准。
- Steam 的首页层级、订单路径、购买流程、后台菜单和支付样式属于项目/PRD特定选择，不据此添加通用组件清单。
- 修复后版本若在独立 RUN 中重新发现问题，应按规范现有章节归类；只有出现跨项目可复现的缺口或规则冲突，才升级为新通用条文。

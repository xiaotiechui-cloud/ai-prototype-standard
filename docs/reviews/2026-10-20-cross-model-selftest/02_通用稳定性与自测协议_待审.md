# 通用稳定性与交付自测协议：待审条款

> 后续状态：用户已批准本轮1～8；本候选协议已去重归入活动规范STD-QA-001等原章。保留CM编号用于追溯，不作为第二套执行标准；当前见[确认与落实](04_确认与落实.md)。

本文件是具体修订建议，不是活动规范；CM编号仅用于审阅。拟在批准后分别并入原权威章节，不整篇加入AI默认提示词。不增加第11份主交付物，不绑定某家模型、浏览器自动化库或开发框架。

## CM01：先确定预期，再生成与验证

AI应按既有优先级读取PRD、用户明确决策、已批准项目契约和适用规范，为本轮形成可执行预期。每项记录来源、适用端、对象、操作、可见结果、数据变化、不得出现的副作用、恢复行为及相应用例。已有统一模型和01/03/07字段优先复用。

对UI至少声明页面分区及顺序、各区职责、分栏/层级、使用的尺寸令牌、滚动归属、主要动作位置、窄/矮视口策略。人工认可参考存在时，应抽取具体契约，不能只写“参考最终版”。本项目PC商品详情可固定左侧媒体及长资料、右侧基本信息及购买卡等已认可安排；其他页面类型按其任务选择模式。

标准默认值由AI直接采用；合理设计推断写明依据和可替换范围，不冒充用户批准。业务缺口影响合法流程、资金、权限或关键布局时登记待确认，继续独立部分，不把整个项目退给用户重写PRD。

验收预期应在实现前保存基线，修复期间不得以当前HTML行为反推预期，也不得为通过检查而删用例、移出失败分母、降低热区或改业务规则。真实需求变化按变更流程更新依据、预期与受影响测试，保留前后版本。

## CM02：能力声明决定可证明范围

开始实现/验证时声明本轮工具实际支持什么；不能仅按模型名称推断能力。

| 能力 | 应报告内容 | 不具备时 |
| --- | --- | --- |
| 读取/写入文件 | PRD与模块实际读取记录、产物路径 | 请维护方提供阶段包；不能声称已读本地路径 |
| 运行代码与构建 | 可用运行时、构建和检查方式 | 保留未执行项；不能把生成脚本当已运行 |
| 真实浏览器 | 浏览器版本、实际打开方式、点击/输入/滚动能力 | L4未验证，不准以VM/状态渲染替代 |
| 视觉与测量 | 截图、元素实际矩形/计算样式、支持的视口 | 缺少的方法和视口分别留缺口，不写全视觉通过 |
| 原生入口 | 文件选择、下载、剪贴板、外部唤起等实际可操作范围 | 页面内注入数据只证明后续逻辑；未覆盖原生入口须明示 |
| 环境范围 | 操作系统、浏览器缩放、设备比例、是否有真机 | 桌面模拟不能自动升级为真机/原生手势通过 |

缺少能力的工具可交付设计评审稿及已执行范围内的证据；最终关卡仍按现行标准判断。能力缺口不构成删除必需交互或标为不适用的理由。可由具备能力的执行方接续固定产物验证，不默认要求用户逐按钮排查。

## CM03：布局和交互通过可复用契约收敛

使用统一的端、组件模式和数据模型，明确共享行为与实例覆盖。布局数值引用唯一令牌，状态、动作、文案和数据依赖由统一配置驱动；禁止同一事实在各页面各写一套常量。

中文作为主显示，内部状态码可供追溯，但不能直接当用户可见按钮文案。按用户已确认的方向保留真实交互、使用灰度线框：媒体仍有切换/预览等行为，视觉采用灰度占位与文字，不生成彩色封面、品牌包装或渐变。成功/错误/警告/焦点也使用明确的灰度表现并配文字，不能靠颜色单独传递状态。业务区隐藏多余滑块但保留滚动及键盘可达；评审说明/宽表的滚动按其各自规则处理。

经过验证的共用外壳、层栈、请求隔离等可作为固定基础实现；项目只配置内容和明确覆盖。未经真实验证的候选代码不称为稳定基础。允许不同技术实现的前提是选择明确的实现方案，保留同等行为和可测试接口；采用现有运行时的项目仍须遵守其接口，不能因本待审稿擅自更名或取消现行data-act约定。

规范稳定的是职责、层级、状态、数据和可观察结果；没有精确参考时，不承诺不同工具所有像素相同。有精确参考时明确参考视口、业务画布实际尺寸、允许变化和容差依据，不采用临时拍定的统一像素误差阈值。

## CM04：真实入口清单与双向覆盖

从模型/注册表形成入口清单，再与真实页面中的可操作元素核对。入口包括业务导航、表单、媒体、页签/筛选、分页/选择、弹窗/确认、端/页面/状态/组件评审控件、阅读器、图示、下载等。

每类实际可用的公共入口至少执行一次真实操作并验证结果。公共入口指不同触发位置或处理路径，不要求遍历同一表格的每一行；重复实例应覆盖参数差异和至少两条不同ID记录。测试某动作的直调函数、另一处按钮或下拉选择，不能代替独立按钮自身的事件链。

| 核对方向 | 必查结果 |
| --- | --- |
| 模型 → 页面 | 必需能力有可达入口，缺失/隐藏/禁用有业务依据 |
| 页面 → 模型 | 每个控件有职责、状态与动作依据；无无主入口或误加能力 |
| 入口 → 处理 → 结果 | 点击命中正确处理，传递当前对象，产生预期副作用/反馈 |
| 共享 → 实例 | 共用处理器可用且实例参数正确，不因共用就跳过端和对象差异 |

禁用控件验证禁用原因、触发条件和恢复方式，不能靠永久禁用来消除失败。状态预设可用于设置初态，但主链必须随后通过业务入口操作；逐状态渲染和逐入口点击分别计数。

## CM05：以风险和实际能力定义测试集合

每端独立执行适用P0主链，PC通过不能代表移动端通过。高影响或有复杂副作用的动作，按适用性覆盖成功、取消、失败、结果未知/超时、重复提交、权限变化及恢复；不机械生成所有状态的笛卡尔积。未支持的业务不要凭测试要求新增，裁剪要有可审阅依据。

至少准备能区分常见错误的确定性夹具：

| 夹具类别 | 要区分的情况 |
| --- | --- |
| 两条不同ID且内容不同的记录 | 打开/复制/编辑的是B，不能实际操作A |
| 空集合、单条、多页、末页 | 真实空态、禁用分页、选择范围和统计口径 |
| 长标题/长字段/多行资料 | 换行、详情区分配、按钮与关闭可达 |
| 无效/失效对象 | 删除、下架、规格失效、权限改变后的重验与恢复 |
| 成功、失败、未知 | 失败不当空结果，支付未知不当成功，支付与交付分离 |
| 乱序和重复响应 | 旧请求晚完成、新请求先完成、离页后旧回调、重复点击 |
| 草稿/生效版本与变更值 | 保存与发布边界，消费者读取最新事实，历史快照不被改写 |

随机数据使用可复现种子或保存输入快照。测试前重置说明状态和业务数据，避免用例间污染；同时保留不重置的真实跨页主链验证。外部服务结果可由明确模拟夹具控制，不能把模拟通过称为真实支付或供应商验证通过。

## CM06：同时断言变化与不变

检查不止“显示成功提示”。每项用例应说明：触发前关键事实、实际操作、触发后可见结果、数据变化、应保持的状态、控制台/错误日志以及关联端的结果。

| 行为 | 应验证变化 | 应验证保持 |
| --- | --- | --- |
| 查看/预览 | 打开当前对象的只读内容 | 不建单、不创建批次、不推进任务或生效版本 |
| 取消确认/关闭子层 | 关闭当前层、恢复父层与焦点 | 业务记录、父层草稿和选择未被错误提交/清除 |
| 保存草稿 | 草稿和版本更新 | 未发布内容不进入对外生效数据 |
| 发布/保存生效配置 | 对应消费者实际更新，必要缓存失效 | 不串对象，不改历史交易快照 |
| 切页/切端/新请求 | 新上下文独立工作 | 旧回调不能改当前页数据、loading、成功状态或导航 |
| 支付查询 | 根据权威模拟结果进入相应阶段 | 用户口述不能直接改已支付，未交付不能显示已交付 |

配置闭环从生产者实际修改开始，继续走到读取该数据的页面/端；不能仅检查写入变量或保存提示。应检查一次被修改值确实改变消费者、一次合法清空不被默认值偷偷补回。日志、审计和埋点按既有端边界验证，审计before/after必须来自真实前后快照。

## CM07：UI布局必须有渲染证据

按现行端规则及项目契约选择目标视口，并加入窄/矮边界与长内容。已有1440/1920等要求保留；外部窗口宽度不能当业务画布宽度。记录浏览器缩放、评审外壳宽度、业务画布实际宽高、内容可用区及滚动容器。

| 检查对象 | 具体断言与证据 |
| --- | --- |
| 页面分区 | 实际元素顺序和分栏符合契约；长资料不被塞进不相干的购买卡；空字段不留巨大空壳 |
| 尺寸和热区 | 实际矩形/计算样式满足适用令牌和登记例外；不因缩小字体或热区硬塞布局 |
| 主操作/导航 | 可见、可点、无覆盖；可滚到主操作/关闭/末项，不能用overflow:hidden掩盖丢内容 |
| 弹层 | 宿主坐标、遮罩覆盖范围、父子层级明确；长内容内部滚动，主动作与关闭可达 |
| 退出/滚动/焦点 | 一次Esc退最上层；背景按规则锁定；滚动不串层；焦点进入与返回正确 |
| 表格与说明 | 业务表按端规则铺开，说明宽表局部滚动；无非预期整页横向溢出或中文逐字竖排 |
| 评审工具 | 说明、描边、组件选择不改变业务布局/身份/选中对象；端按钮自身可交互 |
| 文案和线框 | 中文主显示；媒体与状态符合灰度线框，错误/成功/禁用仍可区分 |
| 图示与阅读器 | 全文/图可读、缩放实际改变大小，目录/历史/下载对象同步；不能只验证面板能打开 |

截图用于核对具体状态的可见布局，几何数据用于定位尺寸/裁切/宿主问题，真实操作用于证明可达与反馈；三者互补。不得凭一张首页截图判定所有弹窗、端或页面通过。比较认可参考时对齐相同端、数据、业务状态、画布和视口；不把无关的示例文字差异算成布局缺陷。

浏览器元素可见或DOM存在不代表用户点得到。对重点控件记录遮挡/命中测试或实际点击反馈；隐藏滚动条后实际滚动到尾部，确认并未禁滚。

## CM08：失败由AI修复并完成影响回归

实现错误已有明确依据时，AI直接修复实现、同步受影响MD和模型、重新构建；无需把每个常规bug交给用户决定。修复后必须复测原失败项及依赖链：

| 修改范围 | 回归范围 |
| --- | --- |
| 共用层栈/关闭/分发 | 采用该能力的各端、父子层、取消/确认/Esc与焦点 |
| 请求隔离 | 新旧请求、切页/端、重置、关闭和loading归属 |
| 数据模型/配置 | 生产者、消费者、详情/列表、统计与历史快照 |
| 布局令牌/外壳 | 适用端和视口、长内容、弹层、说明/阅读器 |
| 文档/内嵌内容 | 独立与内嵌一致、目录、链接、下载、图示和布局受影响区 |

回归集合由依赖决定，不只“刚改的按钮再点一下”，也不每次无理由重复所有检查。保留原失败、修复内容及复测批次。若预期冲突、缺真实工具、外部依赖不就绪或资源限制无法完成，准确停在该依赖范围，报告剩余缺陷/未验证与补验办法，不自动改为通过。

## CM09：证据绑定实际被测文件

验证计划和实际结果分开，结果写入既有07/08体系；不新增另一份人工维护的主台账。允许08通过检查ID/运行ID引用同源的`_checks/`实际记录。记录至少包括：

- 规则基线、内容修订、实际模块/项目契约哈希，PRD基线；
- 用例计划版本/哈希、预期来源和夹具快照/种子；
- 被测HTML及其他相关产物SHA-256、构建标识和运行ID；
- 操作入口、前置条件、执行步骤、预期与实际数据/画面；
- 浏览器/系统/视口/缩放/实际画布，执行者、时间、日志与截图位置；
- 结论、缺陷、复测关联、未验证范围和原因。

不读取附件中的“已通过”日志来冒充本次执行。证据位置须真实存在，未执行项实际结果留空；模板和示例不得填入虚构执行日期或通过状态。

**避免内嵌08的哈希循环：** 08预先引用运行ID和外部证据相对路径，最终文件构建固定后，执行结果及完整文件哈希在`_checks/`封存；08的本批次实际结果可从同源记录查阅，未执行前不预填通过。不要为了把最终哈希写回内嵌08再次改变HTML。若工具确需将摘要写回MD并重新内嵌，则产生新产物，旧证据仅证明旧哈希；应重做结构/构建/同源检查，并按改动影响完成所需真实回归。不能将上次通过直接改成新哈希。

07/08的状态与计数由同一实际记录生成或引用；构建源、探针和自动化实现仍放交付目录外，`_checks/`只是证据附件。交付的单文件HTML仍不依赖该目录才能运行；附件缺失时应判证据不可复核，不能视作运行依赖。

## CM10：准出不能由平均分决定

保持现行Gate和P0/P1/P2定义；本方案细化其执行，不把原型通过升级成生产上线通过。

建议以下条件作为对应原型验证范围的必要条件：适用硬约束无已知违反、各端P0主链通过、公共入口无未处置的缺失或空动作、阻断布局无遗留、必需验证无缺证或未验证。P1/P2遗留明确影响、处置/补验计划及接受状态，不擅自推定用户接受。

“阻断布局”指无法到达关键动作/关闭入口、重要信息裁切不可恢复、遮挡导致误操作或破坏适用硬约束等；普通视觉细节按影响分级，不全部升级成P0。高风险失败不能被总体95%等平均通过率掩盖，未执行不可从分母删除。

分别给出计划总数、适用/不适用、已执行、通过、失败、阻塞、未执行及复测范围；入口覆盖和TC数量不是同一分母。实际结论仍只用现行“通过/失败/未验证/不适用”，阻塞属于未验证。第一轮可交设计评审稿；只有满足所需关卡才宣布达到相应交付状态。

## 用试跑2.0反查本协议是否有针对性

以下是建议新增或强化的验收方式，**不是本轮浏览器执行结果**。缺陷来源为前轮局部隔离观察和源码分析。

| 已观察问题 | 会抓住它的检查 |
| --- | --- |
| 顶部端按钮调用未定义函数，但下拉能切 | 分别点按钮/下拉，检查切端结果和控制台；CM04 |
| QR预设不驱动实际支付状态 | 预设/业务流程分开，真实点击查状态；CM04/06 |
| 取消协议关错父层、重开丢选择 | 打开父层→子层→取消/Esc→重开，对照草稿/焦点；CM06/07 |
| B订单复制A、PC查询跳APP | 两条不同记录，每端独立主链；CM05/06 |
| 已支付与交付状态混用 | 结果未知/支付成功未交付分别造数据，验证状态和允许动作；CM05/06 |
| 草稿提前生效、搜索配置未消费 | 从后台编辑到前台读取，分别验证草稿/发布及合法清空；CM06 |
| 查看赠送即新建批次、审计before错误 | 操作前后数据快照、只读不变和审计原值；CM06 |
| 旧回调结束新loading/写别页 | 可控乱序响应、跨页/端并断言新上下文不变；CM05/06 |
| 商品价格改99而规格仍10 | 从配置到规格选择/购买/订单逐步核对同一事实；CM06 |

这些用例应关联原有TC/CHK及缺陷，优先合并重复用例，不靠继续增加测试条数营造已充分验证的印象。

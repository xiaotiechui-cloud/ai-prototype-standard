# 页面、布局与组件对比

## APP首页

在相同1440×900浏览器视口下，试跑17 V1.1首页的可见顺序为：顶部标题/搜索/客服 → 文本促销Banner →「我的订单／搜索游戏／联系客服」三个快捷项 → 热门推荐 → 双列商品 → 底部「首页／我的」。人工V1.0及V1.5包首页为：顶部商城/搜索 → 轮播Banner → 商品排序 → 商品列表 → 底部一级导航；没有该三项快捷区。截图：`_data/trial17-v11-home.png`、`final-standalone-home.png`、`final-v15-home.png`。

试跑17的01把相关区域拆为`APP-HOME-01-C01`（标题/搜索/客服）、`C02`（首页搜索）、`C03`（客服入口）、`C05`（关键词/快捷标签，说明为快捷导航入口）。V1.1截图中搜索和客服分别再次出现在C05实际区域；01没有给这两项重复的任务收益/理由。PRD V1.6 §4.1 的HOME-03（原文件第503行）要求提供搜索、我的订单及企业微信客服入口，并没有要求同一目的地在首页两个区域重复。

人工V1.5包的01 §1（第51～52行）明确记录其项目特定决定：首页不放个人功能入口，订单/客服常驻于「我的」。该选择不能无条件推广为所有商城的固定业务布局；可推广的是现行通用规则：按任务分配导航区域，不把同一入口集合在各区域重复铺设，例外要有实际收益和证据。

## 外壳与整体布局

三份同视口截图都采用独立的评审工具区、手机设备框及业务画布；试跑17的APP业务外框/内部区域由本批次`_checks`登记为320×640 / 288×592，与既有最终设计配置一致。当前证据未显示本轮出现手机壳尺寸或业务画布被纵向拉伸回归。UI差异集中在首页区域组合和内容：试跑17用单块文本促销Banner并插入快捷导航；人工两版用轮播广告区和紧随其后的排序区域。

这属于页面组合/入口职责，不应把某个促销文案、轮播数量、排序字段或商品内容固定成通用规则。现有UI Profile和页面组合规则已要求区域、组件实例、顺序和来源可追溯；本轮证据提示要核对其是否确实落实到实际首页DOM及默认视口截图。

## WEB与ADM

试跑17清单为WEB 13页、ADM 17页；V1.5包为WEB 12页、ADM 16页；人工根目录V1.0为WEB 8页、ADM 16页。PRD版本和最终版HTML批次不同，页面数量不能据此判定多页或漏页。本批次自测覆盖了PC首页/详情/购买弹层关闭恢复、后台配置消费、权限、导出、退款和分页等，但未提供与人工最终版在完全相同页面/状态上的成对截图，因此本轮不下结论说整个WEB/ADM几何已经同等。

## 组件登记

试跑17登记52个共享组件定义、333个页面组件实例；人工V1.5包登记221个定义，人工根目录HTML登记192个定义。两者组件粒度不同。可比重点是C05快捷导航与顶部搜索/客服、底部一级导航的目标关系，以及首页区域顺序，而不是追齐定义数。完整组件ID索引在`_data/`；未复制完整组件说明到报告。

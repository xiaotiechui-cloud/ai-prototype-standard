# 页面职责、导航层级与入口冗余：通用候选条款

日期：2026-10-26。状态：待审核；本轮补充交付依据后重整，尚未写入活动规范。

本稿只提炼通用要求，不规定具体项目的菜单名称、Tab数量或入口位置，不收录项目参考契约。补充的生成方说明用于分析设计依据与记录缺口，其中的具体整改建议未被用户采纳，不作为批准决定。项目证据及来源说明保留在项目本地评审目录，不进入本批GitHub变更。

以下“必须/应/可”均为拟采用强度。N-01～N-06仅是本次评审编号，不是新增稳定规则ID；获批后修订原归口，不建立第二份活动权威来源。

## 本轮调整的重点

从“删除重复按钮”调整为完整的设计约束链：**需求能力 → 页面主任务 → 导航层级 → 入口分工 → 设计依据记录 → 独立验收**。入口重复是结果；需同时约束把功能清单直接填满多个导航容器、未说明的设计假设和只验证文档互相一致的做法。

## N-01 区分可达要求、位置要求与导航层级（拟：必须）

> 生成AI必须区分：功能需要可达、功能必须从指定位置直接进入、已批准的信息架构。这三者不得互相推定。“有明确入口”不自动要求新增独立控件、一级导航项或首页快捷项；“有独立页面”不自动意味着该页属于一级模块。存在指定位置或直达要求时，也不得用其他位置的间接可达替代。
>
> 实现前依据页面主任务，划分全局导航、页面工具、上下文捷径、内容分类/筛选和主操作。一级导航应对应项目主要任务或稳定模块，不由页面数量或功能清单机械生成；数量、名称及呈现形式由项目确定。多个导航区域同时存在时，必须先统一分配职责，不得让各区域各自承载整份功能清单后直接叠加。

PRD未固定呈现方式时，AI应自行提出能覆盖需求且冗余较少的方案，记录推断；不要求用户先代写导航清单。涉及业务范围、指定入口位置或已批准层级的改变，按既有决策流程处理；普通布局选择不另设逐按钮审批。

**检查方法：** 沿“需求 → 主任务/模块 → 入口类别 → 位置/去向”检查。发现独立页面直接升为一级入口、多个区域重复填满同一清单时，核对其需求或任务理由。适用于移动端、PC及后台，不统一各端的导航形式。

## N-02 最小化记录入口职责与设计假设（拟：必须）

> 在01既有导航/模式记录中补充入口职责和设计依据，并与原型关联；同质实例可合并登记，但必须能够定位各实例。不得另建重复手写的功能表、导航表和假设表。可复用需求、页面及组件编号；只有需要独立追踪的入口才新增实例标识。

| 字段组 | 最低记录内容 |
| --- | --- |
| 定位与适用条件 | 页面/组件/入口定位，端、角色、页面状态及可见条件 |
| 任务与分工 | 用户任务、入口类别、所属层级及承载位置 |
| 行为语义 | 目标、携带对象/筛选/草稿、前置条件、预期结果与返回恢复 |
| 需求与设计依据 | 可查来源；哪些是明确要求、结构参考、AI推断或已批准决策 |
| 跨区重复 | 对应入口组、主要承载位置；保留重复的收益、条件、代价与核验方法 |
| 设计选择与状态 | 选择及理由、影响范围、确认状态；需裁决时引用09中的DEC |

低风险、无冲突的通用选择可按模式合并说明；关键层级、跨区重复及来源冲突不得只写“采用通用风格”。没有明确来源的选择应标为设计推断，不能倒写成“PRD要求”或“用户已确认”。任务覆盖与入口实例可由同一模型生成不同视图，不增加独立交付物或默认加载长报告。

**检查方法：** 从原型入口反查任务和依据；从需求反查可达路径及指定位置。重点问“为什么放在此处、为何与另一处并存”，而不只问“是否有按钮”。

## N-03 依据任务语义治理跨区重复（拟：应；保留理由必须记录）

> 同一页面状态下，目标语义、有效参数、前置条件和结果均相同，且没有额外任务收益的入口，不应跨顶部、正文快捷区、侧栏或底部等区域重复堆放，应选择主要承载位置并合并。保留重复时，必须记录可核验的任务收益、适用条件、空间或操作代价及检查方法；“常见”“更方便”“凑齐宫格”不能单独作为依据。
>
> 判断不得只比较名称、URL或数量：相同路由可因对象/参数不同承担不同任务，不同路由也可能只是同一目标的别名。不同形式也不天然证明有不同价值；例如输入控件和搜索导航是否需要同时保留，仍须检查其实际行为与使用场景。

可合理保留的情形包括：长页面首尾关键操作、无障碍替代路径、带业务对象的求助、带预设条件的任务捷径。以上是需核对的例外情形，不是自动豁免。主要承载位置也不意味着每个目的地在全项目只能出现一次；上下文工具无需强行归入一级导航。

不设跨项目入口数量上限，也不要求所有重复收益都做用户研究；任务链、参数差异、平台约束或既有需求可作为依据。只有声称改善效率数据时才要求相应数据。PRD或批准设计明确要求重复时，不得静默删除；若提出替代方案，必须说明影响并按既有流程裁决。

**检查方法：** 在同一端、角色、状态与视口下盘点入口组，比较实际去向、条件、结果和返回；有合理依据的重复与无依据堆叠分别记录。

## N-04 参考组合与裁剪不得制造新需求（拟：必须/不得）

> 使用竞品、认可原型或通用模式时，必须区分结构参考、功能采纳和行为推断，说明采用部分及影响当前选择的不采用部分。组合来自不同参考的导航、工具栏和快捷区时，必须重新核对整体任务分工，不能因各组件单独常见就认定组合合理。
>
> 参考中的功能不在本项目范围时，不得为填满版式补入其他同名入口或虚构新功能。无有效任务的区域可缩减或不展示，但不得据此删除PRD明确要求的区域、直达能力或批准布局；发生冲突时按core第1章裁决并记录。

截图未显示某区域，只能说明在该截图范围内未见，不能证明整个产品不存在该区域。用户认可的最终产物是重要参考，但其中所有细节不自动成为通用规范。生成方说明、其他AI评语或整改建议也不自动成为项目批准决定。

**检查方法：** 分别追踪功能来源与结构来源，检查组合后的职责冲突、范围外补位和来源夸大；不得以“参考图就是这样”替代定位和解释。

## N-05 去重须同时保持任务覆盖与内容优先级（拟：应；保留已确认能力为必须）

> 页面应优先服务其主任务，导航和工具区不应因无依据重复挤占主要内容。精简入口必须保持需求能力可达、业务上下文、权限校验及异常恢复；已确认的直达要求、入口深度或连续操作路径必须保留，或经过明确变更。
>
> 不为保持快捷区、网格或导航项数量而填入无关任务。缩减区域后须检查长内容、空/失败、游客/登录以及窄/矮视口下的内容与操作可用性，不设跨项目固定卡片数量或首屏露出数量。

**检查方法：** 对照调整前后任务路径和主要内容布局，验证能力未丢失、上下文与返回正确、未形成新的权限旁路；视觉布局需实际视口证据，不能用控件数量替代。

## N-06 独立验收分别核对需求、设计依据与实际行为（拟：必须）

> 验收AI必须从固定PRD、适用规范和批准决策建立预期，再核对入口分工及原型。文档与HTML同源、彼此一致，只能支持一致性结论，不能单独证明需求覆盖或信息架构合理。
>
> 检查至少区分：需求/指定位置覆盖、已确认层级符合性、跨区重复及其依据、入口行为与返回恢复。缺少设计记录、违反明确要求和无依据重复分别记录；审美偏好、合理替代、待定产品选择与可证实现缺陷不得混为一类。严重程度按受影响任务和既有分级要求判断，不因“布局不好看”直接判P0。

已有验收的活跃DEF为零，只说明该轮已记录问题的状态，不证明所有设计选择合理。新发现应注明原轮范围、基线与证据，按适用流程登记缺陷、建议或新变更；不能未经核对就断言既有验收漏检。新候选条款尚未批准或不适用于原项目时，不追溯据此判旧交付违规。

**检查方法：** 静态盘点可报告入口/文档事实；实际点击、权限、返回及视觉表现必须有对应执行证据。未执行项保持未验证。生成方自述可补充依据，不能代替独立行为验收。本稿不代表原型已通过验收。

## 通用边界示例与验收提问

| 场景 | 处理原则 | 核验问题 |
| --- | --- | --- |
| 需求只写某能力需有入口 | 可由现有合适入口承担，不自动增设多处控件 | 能否完成任务？是否另有位置/直达要求？ |
| 多个导航区域分别放齐功能清单 | 重新分配各区域职责 | 每个区域和重复项各自解决什么任务？ |
| 同目标但携带当前业务对象 | 核对是否为有效上下文捷径 | 对象是否实际传递、带来收益且受正确权限约束？ |
| 长页面首尾重复关键操作 | 可有理由保留 | 是否作用于同一当前对象、避免重复提交并正确反馈？ |
| 参考中某区域的功能不适用 | 不补位制造功能；按要求裁剪或提请裁决 | 区域本身是否为明确要求？移除是否丢失能力？ |
| 文档、组件表与原型完全一致 | 仍须独立核对需求及设计依据 | 是否一致地实现了未经批准的假设？ |

## 7. 设计系统：低保真视觉基线

### 7.1 设计令牌

默认输出保留点击、输入、弹窗、滚动等真实交互的灰度线框。媒体使用灰度占位和文字，禁止自行改成高保真品牌网站、营销卡片墙、彩色封面、渐变或大面积装饰图；成功、错误、警告和焦点同样遵循灰度令牌，并配可读文字/图标。项目明确批准的视觉覆盖按第 1.2 节登记。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#f4f4f4` | 页面背景 |
| `--panel` | `#ffffff` | 面板/卡片背景 |
| `--ink` | `#242424` | 主文字 |
| `--muted` | `#6b6b6b` | 辅助文字 |
| `--line` | `#cdcdcd` | 边框/分隔线 |
| `--primary` | `#343434` | 主操作/深色 |
| `--error` | `#333333` | 错误/危险，配错误文字/图标和强调边框 |
| `--success` | `#444444` | 成功，配成功文字/图标 |
| `--warning` | `#555555` | 提醒，配提醒文字/图标 |
| 后台菜单 | `#3a3a3a` 深灰底、白字；选中态按第 12.2 节 | 侧边导航 |
| 禁用背景 | `#eaeaea` | 禁用输入/按钮 |
| 焦点环 | `#525252`，2px，offset 2px | 键盘可见焦点 |

### 7.1.1 最终版参考设计配置档案

为提高同一规范下的生成稳定性，每个项目必须在 00/01 登记一个 `uiProfileId`、`uiProfileRevision`、`uiProfileSource` 和 `uiProfileHash`。本轮默认参考档案来自已确认的最终版稳定特征，包含灰度令牌、字体层级、4/6/8/10/12/16/24 语义间距、移动外框、桌面/后台容器、控件密度、卡片、弹层和图示基线；这里只固化可跨项目复用的结构与令牌，不把商城页面、菜单数量、商品卡宽度或业务入口直接推广。

档案至少包含：

- 色彩、字体、行高、间距、圆角、边框、阴影、焦点和控件密度令牌；
- 客户端、桌面 Web、后台、阅读器和图示的页面壳层与区域顺序；
- 标准组件的结构、变体、状态、尺寸和默认模式；
- 弹层宿主、宽高档、安全距、正文滚动和关闭出口；
- 图示灰度样式、节点类型、标签规则和缩放基线。

生成器必须从已登记档案读取默认值；同一 `uiProfileHash` 下不得自行重写共享令牌。项目覆盖必须写入 01/03/09，注明字段、原值、新值、理由、批准依据和验收范围。未登记的临时 CSS、组件变体或页面壳层不计入稳定生成结果。

`uiProfileHash` 标识生成前实际采用的设计配置内容，而不是生成后某段 CSS 或 HTML 的摘要。档案必须有可定位且可复算的快照，覆盖本节规定的令牌、页面壳层、组件变体及弹层/图示默认值；生成记录需指向实际读取位置并说明字段映射。记录档案版本、哈希算法、截断长度以及必要的规范化/序列化方法；输出 CSS/HTML 指纹另列为产物指纹。档案可以是文本、JSON 或项目已有模型，只要满足同等追溯性，不强制特定文件格式、路径、框架或完整哈希长度。没有生成前消费证据时，不得仅凭 `uiProfileHash` 宣称稳定生成已证明；项目覆盖仍按 01/03/09 登记。

### 7.2 字体与排版

- 正文字体：`"Microsoft YaHei", Arial, sans-serif`；不加载外部字体。
- 正文 14px/400；字段标签、辅助文字 12～13px/400；页面标题 20px/500；组件标题 16～18px/500，同级选定后统一。
- 组件说明正文默认 13px、说明表格默认 12px；先扩宽可用空间、调整分栏与换行，不以持续缩小字号适配。窄屏宽表保留完整列，允许局部横向滚动。
- 行高 1.6～1.9；长文阅读建议 14px、行高 1.8；长表格内容顶部对齐、允许换行。
- 金额、数量、时间使用统一格式：金额两位小数并带币种/单位；时间写明时区或采用统一本地格式；计数带单位。
- 长文本 `overflow-wrap:anywhere`；不在表格中把中文逐字拆行。

### 7.3 控件与热区

| 端 | 最小高度 | 说明 |
| --- | --- | --- |
| 移动客户端 | 44px | 主要交互热区至少 44×44 CSS 像素 |
| 桌面客户端 | 默认至少 40px；登记的紧凑变体至少 36px | 同组使用相同密度 |
| 管理后台 | 40px；紧凑表格操作可为 34px | 焦点与点击热区必须明确 |
| 评审控件 | 40px | 不进入业务画布 |

规则：

- 按钮为矩形，主按钮深灰白字、次按钮白底灰边；
- 普通筛选按钮为可换行矩形，不是胶囊；客户端单行状态导航按第 10.9 节不折行，空间不足采用横向滚动或下拉，不降低热区、不裁切选项；
- 选中态唯一，使用 `aria-pressed`/`aria-current`；
- 禁用必须有原因说明，不得用禁用掩盖缺失逻辑；
- 输入框白底、1px 灰边、错误 2px 错误令牌边框＋文字；
- 复选框/单选框默认采用原生控件，不拦截默认行为；自定义等价控件按第15.3.1节保持语义与可操作性；
- 图标使用内联 SVG，`currentColor` 随文字变色；不引外部图标库。
- 图形尺寸与可点击热区分别登记；小图标不意味着热区可缩小，相邻热区不得重叠。后台 34px 仅用于登记的紧凑表格操作，不下放到常规表单。多行文字和文字缩放允许控件自然增高，不用固定高度裁切内容。

### 7.4 画布与布局

| 端 | 评审外壳 | 业务画布 |
| --- | --- | --- |
| 移动客户端 | 最大宽 1440px；左画布列约 384px、右说明列 1fr；间距 24px | 默认居中手机外框 320×640 CSS px（border-box）；内部业务区 288×592 CSS px，正文独立滚动 |
| 桌面 Web | 最大宽 1480px；画布通栏，说明在下方 | 宽屏多列，容器内边距 24px，内容最大宽 1200～1280px |
| 管理后台 | 最大宽 1480px；画布通栏，说明在下方 | 左侧菜单 220px（收起 64px）＋右侧工作区，最小宽 0 |

通用：

- 所有网格/弹性子项设 `min-width:0`，允许收缩；
- 主列表不靠 `overflow-x:hidden` 裁列；
- 窗口/画布宽度变化时使用容器查询，不只看视口；
- 桌面/后台在 1440px 与 1920px 检查无必须拖动的底部横向滚动条；
- 移动端默认 `frameMode=phone`，在分配的画布列内水平居中，保留手机外框两侧自然留白，不将外框拉宽填满整列。手机外框使用 `width:320px; height:640px; box-sizing:border-box; flex:none`，不得仅使用 `min-height` 或由内容撑高；顶部栏、底部操作栏使用 `flex:none`，正文滚动区使用 `flex:1; min-height:0; overflow-y:auto; overflow-x:hidden`。项目确认的其他尺寸在 01/09 登记完整宽高、依据和验收范围。
- 手机外框统一令牌：边框 `2px solid #8d939b`，圆角 `22px`，内边距四边 `14px`，背景 `#fbfbfb`，无装饰阴影；使用纵向 flex、`position:relative`。顶部听筒为非交互装饰：宽 `72px`、高 `6px`、背景 `#c9cdd3`、圆角 `3px`、水平居中、下间距 `10px`、`flex:none`，不进入 Tab 顺序或业务组件清单。外框边线是评审装饰，不替代第 7.1 节业务边框令牌。
- 评审展示宿主、设备外框、内部业务区与正文滚动区分别记录。默认无缩放时：外框 320×640，扣除两侧边框/内边距后内部宽 288；扣除上下边框/内边距和听筒 16px 后业务区高 592，业务区包含页面顶栏/底栏，正文高度再扣除这些栏。不得将 320×640 外框标注为内部业务区尺寸；不得按页面有无底部 Tab 改变外框尺寸或四边内边距。
- 默认外框无需逐项目申请例外；在 01/03 登记所用规格、内外矩形和正文滚动宿主即可。无外框 `frameMode=none`、其他皮肤/尺寸/内边距或缩放属于项目覆盖，须记录理由、批准依据、实际渲染矩形和验收范围。窄宿主优先调整评审分栏，仍不足时按登记方案整体缩放并检查文字、热区与操作可达；不得靠裁切外框或另加空白占位挤压业务区。外框和听筒不得遮挡业务内容、截获点击或改变弹层/正文滚动职责。
- 业务画布内滚动区域默认隐藏多余的装饰性滚动滑块，同时保留滚轮、触控、键盘及程序化滚动；不得用 `overflow:hidden` 代替隐藏滑块，也不得全局禁用页面滚动；
- 可读性、平台发现性或项目契约要求显示滚动滑块时，在 01 记录理由与验收范围；评审说明列独立滚动时只在悬停/聚焦显形。

上表为默认几何基线。目标设备、实际内容或已确认设计要求需要例外时，在 01 登记目标值、依据、确认记录和验收范围；不得降低第 7.3 节的热区要求来凑布局。外壳宽度、业务画布宽高、内部可用空间分别记录，不得以外壳或配置目标值冒充实测画布尺寸。

长内容在明确的正文滚动区内可达；常规与矮视口下，正文末端、顶部/底部操作均应可达，不通过无限拉长设备框或裁切内容解决。响应式依据实际容器宽度；画布尺寸标注随容器变化同步，更新标注不得重建业务画布。记录外壳宽度、业务画布宽高、正文 `clientHeight/scrollHeight`，不得以视口高度或外壳高度替代业务画布尺寸。

同一语义组件在不同页面默认复用相同的灰度令牌、层级、间距和反馈结构；确需单页变体时在 01/03 登记变体 ID、适用状态和依据，不以临时样式覆盖共享组件规则。

#### 7.4.1 语义间距与布局选型

以下为建议默认值（CSS px），不是所有间距必须为 8 的倍数。项目按语义选用，紧凑/其他变体登记后统一复用；不替换上文手机外框、桌面 24px 或后台约 20px 的内边距。

| 语义 | 建议默认值 |
| --- | --- |
| 标签与控件 | 4 |
| 紧凑纵向内容 | 6 |
| 同组动作 | 8 |
| 卡片内边距、移动网格、字段网格 | 10；紧凑卡片可登记为 8 |
| 桌面网格 | 12 |
| 业务分栏 | 16 |
| 评审主分栏/外部间距 | 24 |

在 01 按任务选择居中单列、主次分栏、自适应网格或菜单＋工作区，记录区块职责、顺序、最小可读宽、列宽预算及收拢条件。预算使用实际业务内容宽，扣除菜单、边框、内边距和间距，不直接使用整个浏览器宽度。主次分栏在“各列最小宽之和＋间距”无法容纳时按登记顺序收拢；网格可用 `floor((可用宽＋间距)/(卡片最小宽＋间距))` 估算列数，再用长内容和完整动作验证。不得把参考商城的 300px 卡片、860px 断点、1.15:1/1.35:1 比例或功能分区强制用于通用项目。

同类表单复用字段结构与标签位置，控件顶部/文字基线按所选结构对齐。长标签和校验信息自然扩展，不逐字段用负边距、裁切或缩小字号强凑；标签间距建议 4、字段间距 10、动作间距 8，不强制三列表单。后台保存/关闭仍按第 12.9 节放在右上角。

#### 7.4.2 几何合同与实测

在 01 按端、布局、密度/变体建立可复用合同，03 实例引用并登记覆盖。合同包含来源版本/批准依据；展示宿主、外框、内部业务区、内容区的目标矩形；布局角色、顺序、列宽预算、间距和收拢条件；组件字体/行高、图形与热区、边线、圆角、内边距、动作位置；滚动宿主、固定区、正文末端可达策略。

实际验证在 08 记录视口、容器、缩放、状态、数据夹具、截图和实际矩形/计算样式，目标值与实测分列。只对齐相同端、组件变体、状态、容器及缩放比较。CSS 声明或配置标签不是测量；无测量保持未验证。需要容差时在检查前按项目登记依据，不临时发明全局像素阈值，也不在失败后放宽阈值。

### 7.5 卡片、空态与反馈

- 页面标题、区块标题、字段标签、辅助说明、主要/次要动作使用稳定层级；表单标签与输入关系清晰，必填、错误、只读/禁用原因就近呈现；
- 表格统一表头、行高、单元格对齐、空值与操作列呈现；同类页面不因装饰样式改变列语义或动作优先级；
- 卡片、表单、表格、弹层、提示条采用一致的灰度边框、间距和标题/动作区结构；不同业务状态同时通过文字或图标表达，不只依赖色差；
- 卡片：1px 灰边、白底、标签＋值；不堆叠装饰阴影。
- 空态：虚线/浅边框、原因、下一步操作；不得只显示“暂无数据”。
- 错误：就近显示，说明可执行动作；不暴露内部错误码/凭证/堆栈。
- 成功：工作区内 toast/提示条 + 列表/数据同步；不只写控制台。
- 表格：表头清晰，数字/金额/时间格式统一；空值用 `—`，不等同于 0。
- 加载：骨架或进度，保留筛选与页面结构；不以空白页替换整个工作区。

#### 7.5.1 面板结构与弹层尺寸

常规卡片、按钮、输入采用矩形、1px 灰边、0 圆角、无装饰阴影；错误/焦点使用第 7.1/7.3 节的明确状态边线。卡片的媒体、标题、详情、动作结构稳定，媒体占位、加载与结果遵循同一几何合同。长文省略须可取得全文，不省略掉关键金额、错误原因或必需动作。手机外框 22px 和桌面预览框 8px 圆角不继承到业务控件。

| 弹层类别 | 桌面/后台建议最大宽 | 选择依据 |
| --- | --- | --- |
| 确认 | 400px | 对象、影响与明确决定 |
| 普通 | 600px | 单任务、常规信息/表单 |
| 复杂 | 920px | 确有分组、多列或复杂编辑需要 |

选择能完整承载任务的最小档，而非所有弹窗固定 920px。实际宽还受所属宿主约束：桌面两侧安全距各至少 16px、移动居中各至少 12px；移动底部面板可贴业务区边缘。居中弹层最大高建议为业务宿主可用高度的 80%，底部面板为 88%，同时服从更严格的安全距；不用整个 HTML 的 `vh/vw` 冒充宿主尺寸。矮宿主、文字缩放/键盘场景保留标题和必要动作，正文 `min-height:0` 独立滚动；确需宿主内全屏变体在 01 登记。

面板白底、1px 中性边线；后台矩形，移动可登记 16px 圆角（居中四角，底部面板仅上角）。遮罩建议独立令牌为 45% 黑色透明度，不降低父容器透明度；层级按背景＜当前层＜子层＜当前反馈表达，不复制参考源码的固定 z-index。标题 16～18px、正文 14px、辅助 12～13px；后台头部/正文建议纵向 10px、横向 12px，移动正文 14px，动作间距 8px。关闭图形与热区分开，移动关闭热区至少 44×44。反馈相对所属宿主且避让动作/焦点。后台保存/提交/关闭在固定头部右侧，关闭最后，不另加重复底部保存栏。宿主、焦点、锁和退出生命周期只由 `STD-RT-001` 定义。

### 7.6 可访问性

- 所有交互控件可用键盘操作；焦点可见；
- 弹窗打开后焦点进入层内，关闭后恢复触发元素；
- 图标按钮有 `aria-label`/`title`；
- 状态变化使用 `role="status"`/`aria-live`；
- 遮罩/弹层不得让背景可聚焦；
- 颜色不是唯一信息载体，错误/成功/警告同时配文字。

## 8. 评审外壳规范

### 8.1 固定结构

```text
顶部标题区：项目名、PRD基线、交付版本/批次、文档状态、模拟说明
评审控制区：端 / 页面 / QA 状态预设 / 业务资格条件 / 模拟结果 / 业务操作或重置
可选：平台/账号上下文与业务资格条件（评审工具，与页面状态预设分区）
移动端画布上方通栏：当前状态 / 数据来源 / 下一步 / 页面级评审注释
移动双栏主体（桌面 Web / 后台按 8.4 通栏布局）：
  左：业务画布
  右：组件选择器 + 所选组件完整十节说明
底部：流程与图示入口区、完整交付文件入口区
弹层：图示查看、MD 阅读器
```

### 8.2 评审控制

| 控件 | 行为 |
| --- | --- |
| 端 | 只列项目真实存在的端；“全部端”显示全部；切换后清理旧组件、旧状态与旧回调 |
| 页面 | 按端过滤；页面切换后标题、画布、状态列表、组件列表、说明同步 |
| 页面状态预设 | 随页面同步；当前页不适用状态不出现；瞬态状态在切页/切状态时清除；作为独立 QA 控件构造初态，不伪造业务操作结果 |
| 业务模拟条件 | 只提供 PRD 需要的登录、实名/成年、手机号、协议等前置条件；不提供没有业务用途的快捷身份组合 |
| 模拟结果 | 至少支持正常/失败/超时/空数据（按项目适用性）；影响模拟接口与页面状态 |
| 业务操作 | 执行真实模拟提交，产生处理态与结果；不能与“状态预设”混淆 |
| 重置 | 清除输入、错误、计时器、处理中、选中记录，回到明确初始态 |
| 描边 | 默认关闭；只描当前所选组件；不改变布局、不拦截业务操作 |
| 流程与图示 | 打开图示入口区或弹层，不改变业务状态 |
| 完整交付文件 | 打开 MD 阅读器，不改变业务状态 |

端、页面、页面状态预设及平台/账号上下文等独立入口分别可用；用户可见名称中文主显示，英文仅作内部 ID 或辅助追溯。页面状态预设用于 QA 构造初态，不替代业务按钮的真实流程；端切换、来源平台/账号与登录/实名等业务条件分别管理，切换时不得串用上下文。业务提交仍执行原型校验、处理中与结果流程，不可由快捷状态跳过。

### 8.3 当前状态块

必须展示：

- 页面名称与页面 ID；
- 当前状态码与中文名；
- 模拟结果；
- 数据来源（模拟/真实/建议契约）；
- 下一步建议；
- 页面级评审注释（画布外，按归属收集）。

移动双栏的状态块在画布上方通栏，不塞进右侧组件说明列造成错位。桌面 Web / 后台按第 8.4 节布置；状态块保持独立、通栏，不作为组件十节的一部分。

### 8.4 画布与说明列

**移动客户端布局：**

- 第二行左画布（约 384px 列）、右说明；两块同起一行、纵向起点一致；
- 画布块在视口内吸顶并限高，自身可滚动；说明列独立滚动，组件选择器在该滚动容器内保持易达；
- 窄屏（容器宽 <760px）改为上下布局，取消吸顶与独立滚动。

**桌面 Web / 后台布局：**

- 业务画布通栏在上，完整说明移到画布下方两栏；
- 状态块通栏，可在画布上方或画布与说明之间；说明区在容器空间充足时可限高独立滚动，画布不被说明挤窄；
- 后台在 ≤900px 时说明移到下方；≤700px 侧栏转为横向可滑动条，不得整块隐藏。
- 评审外壳的工具区、业务画布、说明区分别响应实际可用容器宽度；优先保证业务画布主任务区域，工具区可折叠/下移，窄容器可收为单列，不以固定侧栏挤压或裁切画布；不得把评审外壳断点直接套作业务页面断点。

**滚动策略：**

- 页面负责外壳整体导航；业务画布、弹层正文、说明列与阅读器各按职责保留必要滚动，隐藏滑块不等于禁止滚动或裁切内容；
- 双栏说明的选择器与正文共用一个主要滚动容器，不再无必要地嵌套固定高度的正文滚动框；说明列滑块在悬停/聚焦时显形，键盘/触控仍可到达全文；
- 单栏说明回归页面流，取消独立限高与吸顶；响应式依据承载内容的实际容器，画布标注遵循第 7.4 节；
- 文档阅读器的宽表/代码/图示各自局部滚动，不撑宽整页。
- 业务弹层的宿主、定位、遮罩范围、全屏例外、关闭生命周期和滚动锁统一遵循 `STD-RT-001`，不在此另设例外条件。

### 8.5 组件选择器

- 采用紧凑下拉/选择器，默认收起；
- 选项格式：`组件名称（完整编号）`；
- 以当前页面注册表列出全部实例，按约定展示顺序排列；当前 DOM 仅用于实际展示与定位校验，不能代替注册表而遗漏其他状态实例；
- 显示当前页组件实例数；
- 选择后立即更新：选中项、当前组件 ID、完整十节说明；原生 select 使用选项语义，按钮组使用适用的 `aria-pressed` 等语义；
- 当前状态未展示该组件时，说明区提示“该组件在当前状态下未展示”，保留定义；
- 选择器不触发页面导航、不改变业务状态、不重置输入或滚动。

### 8.6 辅助描边

- 使用 `outline` 或独立覆盖层；
- 不新增占位元素、不改变 border/padding/margin/宽高/布局；
- 覆盖层不接收指针事件；业务组件本体不设 `pointer-events:none`；
- 仅描当前组件；重复列表项可描当前已渲染的同类实例，并在说明中写明范围；
- 关闭描边后保留选择与说明；
- 描边与键盘焦点相互独立。

### 8.7 评审注释收集

画布内保留用户会看到的业务内容。评审注释、业务提示与字段帮助须显式标记语义及归属；例如 `data-note-kind="review|business|help"`，评审注释再用 `data-annot-owner` 指定归属。设计理由、模拟说明和纯评审引用应标记为 review 并移出画布。

`.hint`、灰色小字或 PRD/规则等关键词只能辅助检查，不能单凭样式类或正则搬走文字。业务提示即使含规则引用也保留其业务含义；归属不明确时先核对，不自动删除。

实现要求：

- 渲染后只收集并移出已标记的评审注释，按 `data-annot-owner` 或最近 `data-component` 归属；
- 页面级注释进入状态块，组件级注释进入该组件的十节说明；
- 保留在画布内的业务文字只去除纯评审编号，不移除用户理解业务所需的提示或帮助；
- 不因移除注释而改变业务布局或文案含义。

### 8.8 图示与阅读器入口

- 图示区默认只列入口，不平铺全部图；
- 阅读器入口列出全部已交付 MD；
- 两者都在业务画布之外，不改变原型状态；
- 关闭后恢复原页面、滚动位置与触发焦点。

### 8.9 评审工具隔离

<!-- RULE-ID: STD-RV-001 -->

选择组件、切换描边、查看图示及阅读文档应局部更新评审区域。除用户明确选择的评审状态外，不得改变业务页/状态、会话、稳定记录 ID、输入/待提交草稿、业务数据版本或业务画布滚动位置。

确需重建业务 DOM 时，必须用相同字段的操作前后快照证明上下文完整恢复；仅重新聚焦输入框不构成恢复证据。工具关闭后的焦点按实际触发入口恢复。

评审控件不得：

- 触发业务接口或写入业务对象；
- 进入埋点；
- 改变业务画布的尺寸、字体、控件文案；
- 与业务动作共用同一状态键导致冲突；
- 在业务画布内显示“评审”“模拟”等标签（模拟说明放画布外）。

## 9. 组件编号、标注与同源说明

### 9.1 `data-component`

每个可操作、数据展示、反馈或状态承载单元必须有稳定的 `data-component="组件ID"`。

- 纯装饰元素可不建组件；
- 同一内容换宿主渲染时，由外层统一标注，不重复写空 ID；
- 组件选择器、描边、文档解析都依赖该属性，不得只在文字中写编号；
- 共享组件定义使用 `COM-*`/`ADM-COMMON-*`；页面实例仍使用页面组件 ID。

### 9.2 组件包装

参考实现使用统一包装函数：

```text
C(id, innerHtml, tag, className, style) → 带 data-component 的 HTML
```

规则：

- `id` 为空时不写 `data-component`；
- 属性值必须转义；
- 不把编号拼进可见标题、按钮文案或卡片内容；
- 组件编号只出现在画布外选择器、说明区与 03。

### 9.3 说明区

- 展示完整十节，不摘要、不默认折叠、不以“详见 03”替代；
- 允许局部滚动，但不能只显示第一屏；
- 组件当前未展示时给出提示；
- 组件缺十节时明确报错，不静默降级；
- HTML 与 03 同源，不得手写第二份。
- 基本信息一行一点；渲染后保留硬换行，字号与宽表遵循第 7.2 节。

### 9.4 数据来源写法

「来源及字段路径」列必须写：

```text
谁产生 ＋ 真实字段路径
```

示例：

- `平台容器可信环境；订单 source`
- `商城服务端商品目录；catalog.products[].id`
- `可售库存服务；skus[].stock`
- `后台运营配置；home.banners[]`

不得写：

- `API-PRODUCT-001 → product.image`（这是文档归属，不是来源）
- `详见接口文档`
- `后端`（过于笼统）

同一字段多处引用时写实际提供方，不写引用方。此规则同样适用于交互逻辑、界面反馈中的字段注释。

### 9.5 共享组件与实例

- 共享定义只写一次完整十节；实例写所属页面、实例差异、引用章节；
- 实例 ID 稳定，不因复用共享定义而消失；
- 共享组件的状态、动作、事件必须在实例处说明差异；
- 删除一个实例不影响共享定义；删除共享定义必须检查所有实例。
- 实例登记适用状态；说明按“共享完整十节＋实例覆盖”合成该实例实际规则。未解析覆盖、缺节或引用失效须报错，不以通用模板句或“详见共享组件”替代。
- 充分性检查具体数据来源、主操作、成功/失败、禁用原因、取消/返回和可判定验收条件；组件数量或字数不构成完整性证明。
- 实例覆盖写明字段、原值、新值和原因/批准依据；合成后的实际十节须完整可执行。几何合同可共享引用，但实际差异、数据副作用和状态适用性不可用引用掩盖。

### 9.6 评审标注边界

| 内容 | 位置 |
| --- | --- |
| 页面名称/编号/版本/状态 | 画布外标题与控制区 |
| 组件名称/完整编号 | 画布外选择器与说明 |
| 技术字段名、接口名、纯评审规则引用、设计理由 | 画布外说明区 |
| 用户需要的业务提示与字段帮助 | 画布内，显式标记业务语义 |
| 按钮文案、业务标题、图片、标签、列表、反馈 | 画布内 |
| 辅助描边 | 仅评审开关开启时，画布内但不占布局 |

禁止：

- 把编号作为标题/按钮的普通文本子元素；
- 为塞入编号而缩小字号、拉高卡片、修改按钮文案；
- 删除编号后失去文档映射；
- 把已标记的评审注释留在画布内挤动业务内容，或仅凭 `.hint` 类名误移业务提示。

缺少任一项，不得视为“完整组件”。

#### 14.4.1 可执行组件合同

沿用 03 的十节，不新增交付物。合同登记稳定 ID、PAT、端/密度/变体、宿主/父层、结构职责、适用状态；数据对象 ID、来源、草稿/已提交/显示快照、未知值和权限；触发、守卫、作用范围、提交快照、防重复、取消恢复；反馈文案、动作可用性、校验和失败重试；样式令牌、字体行高、边框圆角、图形/热区、对齐间距、固定/滚动与目标/实测。状态迁移覆盖离页、身份变化、迟到结果；API/事件区分模拟和真实能力，不伪造业务埋点。关联 TC、夹具、证据和未测限制，计划不写成已通过。

#### 14.4.2 基础控件与通用状态

- 复用同一结构和登记变体；按适用性表达普通、悬停、焦点、选中、禁用、错误、处理中。按钮文案说明真实动作，指针/键盘一致，防重复提交，失败可恢复；图标按钮有可访问名称，不依赖悬停才说明关键含义。
- 输入有外部标签，占位不替代标签；帮助/错误就近，保留草稿、光标和输入法组合，区别只读与禁用。搜索在组合输入期间不误提交；Enter/按钮共用校验，清空输入不暗改已提交查询，历史按批准合同写入。
- 单选当前值唯一，不可选项有原因；上下游字段和显示数据同步，不虚构业务选项。原生勾选与标签热区关联；协议默认不勾选仅适用于协议，不推广到所有多选；全选、半选及权限范围有明确定义。
- 静态标签与可操作标签可辨；长文可完整取得，删除标签的命中不触发卡片导航。
- 组件按业务适用性登记加载、结果、空、错误、超时、未知、无权限、禁用、提交、成功/失败、末端；不为凑状态虚构业务。查询失败不冒充成功零条，未知不当零；显示值、计数、选择与当前提交快照一致，旧响应不覆盖新上下文。原型模拟结果不等于外部事实。

#### 14.4.3 注册表绑定、实例归属与生成阻断

01/03 中的组件注册表是生成输入，不是说明性清单。每个实例必须引用已登记的组件 ID、模式 ID、变体 ID、状态和 `uiProfileHash`；页面组合只能引用已登记区域和模式。生成前必须阻断以下情况：组件 ID 或变体不存在、同一实例出现多个语义、组件合同缺少样式令牌或出口、页面区域无来源、实例覆盖未登记、同组组件绕过共享令牌。通过后再生成 `data-component`、`data-variant` 和 `data-ui-profile` 标记，供 07/08 双向核对。

注册通过后还必须证明实际消费：每个实际采用的变体都能从注册表追踪到渲染结构、有效样式/布局和适用行为。只有 `data-variant`、CSS 定义、Profile 引用或说明文案，不构成变体已实现的证据。07/08 分列“已实现并验证”“已声明但未验证”和“声明效果未实现”；后两者不得按注册齐全放行。组件实例必须属于当前登记页面；共享定义可以跨页复用，但跨页共享实例须显式登记页面归属和适用范围。未登记实例、错误归属、未消费变体和被临时覆盖的共享令牌均阻断构建或验收。

最终版只能作为稳定参考档案的来源证据；未被档案登记的最终版局部实现、商城业务内容和偶然排列不得通过“看起来相似”自动升级为通用规则。

## 15. 标准交互模式库（PAT）

### 15.1 命名与登记

通用模式固定职责、状态、数据副作用、层级和恢复；项目在 01/03 登记具体分区、顺序、尺寸令牌/覆盖及验收。认可原型需提取可执行契约，不只写“参考最终版”；项目特定数值、商城功能和支付承接路径不自动推广。AI在无参考时依PRD选默认模式并标明推断，不要求用户先写这些明细。按需执行细节见 [模式入口](../docs/patterns/README.md)；裁剪须有适用性依据，不能省略已有强制能力。

- `PAT-类别-序号`，类别固定使用：NAV、INPUT、CHOICE、CHECK、ACTION、MODAL、CODE、CARD、LIST、GRID、FILTER、TABLE、PAGE、DRAWER、GALLERY、EXPAND、CAROUSEL、COUNTDOWN、COPY、TIMELINE、NOTICE、FEEDBACK、EXTERNAL、BATCH、EXPORT。
- 每个组件在 01 登记模式 ID；允许项目新增，但需写结构、行为、差异与验证点。
- 优先使用已确认模式；不得为同一行为发明多个模式。

跨区入口治理：

- 同一页面状态下，目标语义、有效参数、前置条件和结果均相同，且无额外任务收益的入口，不应在顶部、正文快捷区、侧栏、底部等区域重复堆放；应明确主要承载位置并合并。保留时必须按第21.5节记录任务收益、适用条件、代价与核验方法，不能只写“常见”“方便”或“凑齐宫格”。
- 不按名称、URL或数量直接去重；同路由可能对象/参数不同，异路由可能为同一目标别名。输入控件与导航等不同形式，也须结合行为和场景判断收益。主要承载位置不意味着全项目只许一个入口，上下文工具不必升级为一级导航。
- 长页首尾关键操作、无障碍路径、带当前对象的帮助、带预设条件的捷径可有合理重复，但必须核对实际收益，不能自动豁免；需求明确要求重复时不得静默删除，替代方案按第1章处理。不设统一数量上限，不要求每项做用户研究；声称基于效率数据时须提供数据。
- 页面应优先服务主任务，不应让无依据重复挤占内容；不为网格或导航数量填入无关功能。精简必须保持需求能力、业务上下文、权限校验和异常恢复；已确认直达、入口深度或连续路径必须保留，或经明确变更。
- 同端/角色/状态/视口下比较入口组；调整后检查长内容、空/失败、游客/登录及窄/矮视口，验证能力、返回与主要内容可用，不设跨项目固定首屏内容数量。视觉结论须有实际视口证据。

职责在第6.7节、字段在第21.5节维护；按需操作见[内容与导航](../docs/patterns/content-and-navigation.md)与[入口检查](../docs/acceptance/actions-and-results.md)。

导航切换页面/任务，页签切换约定视图/状态，筛选改变查询，三者不混用。移动返回恢复来源，一级页面无返回，底部栏在业务区内且不遮末项，二级页按既有规则隐藏。桌面按标识、导航/搜索、用户区分组，不填充重复入口；后台空分组随权限裁剪隐藏。页签唯一选中、计数同一查询口径，单项不强凑两项；切换是否重置按合同登记。查询区分输入草稿与已提交快照，查询/重置/刷新及迟到响应分别验证；不将参考的五项筛选或单行结构通用化，字段排序与手工拖拽排序分开定义。

#### 15.3.1 输入类型与几何隔离

文本输入、textarea、select、radio、checkbox、file、range 等按实际几何类型限定选择器及尺寸；不得用未限定类型的 `input` 宽高、padding 等文本框规则无意覆盖选择、文件或滑块控件。项目使用的每类输入登记尺寸来源与适用变体，不新增全项目同一像素要求。

选择图形与点击热区分别定义，遵循第 7.3 节；同宿主混排时核对选中、焦点、禁用、错误及长标签状态。原生控件保留默认语义与行为；有明确需要的自定义选择控件须提供等同的选中、分组、标签、键盘和禁用语义及可操作性，不以外观替代操作。不得因标签换行将选择图形拉伸，或让相邻标签热区重叠。

按第 29.11 节在固定端/变体/状态/数据/画布下测实际矩形与计算样式，并真实点击控件及 label、用键盘切换、核对 disabled 不改变值；静态选择器检查不能代替此验证。按需试点见[最小输入参考](../reference/implementations/input-kit/README.md)，其代码、令牌版本及验证范围须登记；样例通过不自动证明项目集成通过，不要求所有项目依赖此样例。

#### 15.6.1 对象、列表与数据操作

- 卡片、列表、详情、表格、分页、批量全过程使用稳定对象 ID；重排后仍定位原对象，失效 ID 不回退首条/行索引。卡片按媒体/标题/详情/动作组织，缺失或不可用有状态，内部动作不误触外层导航。
- 摘要、个人信息、指标写明标签、单位、范围、时间与独立加载/失败/未知、脱敏规则；未知不显示为零。列表返回恢复约定查询/页码/滚动，追加去重并显示末端，失败保留已有结果。
- 后台使用真表格，列语义、宽度预算和关键字段可读，不靠强制横拖或裁切。分页覆盖无效页、查询变化、末页删除、条数变化、失败/迟到；显示数据与当前页/总数同源。
- 批量区分本页/跨页范围，稳定 ID 快照、全选/半选、计数与部分失败一致。导出区分启动、生成完成、可下载，核对实际文件内容、字段、范围和权限，不能只凭成功提示。

#### 15.6.2 媒体、长内容与时间

- 图库覆盖 0/1/多项，登记媒体比例、缩略图索引与对象、失败占位和视频清理；占位与结果遵循几何合同。轮播仅在多项启用，悬停/焦点/不可见暂停，手动切换重新计时，离开清理；单项无假箭头/指示器。不推广商城媒体比例或持续时间。
- 展开可取得全文且不覆盖动作；收起恢复约定锚点和展开范围。时间线记录真实时间、事件、结果及获准展示的操作者，排序/同时间项/未知/空态按合同，不补造事件。
- 倒计时采用可信时间来源、统一单位和到期行为，清理/恢复及竞态可验证；客户端计时器不成为交易最终状态权威。

#### 15.6.3 复杂编辑

- 默认在父草稿内编辑，取消不生效；明确批准的即时动作/自动保存单独说明文案、作用范围和恢复，不强套草稿发布。联动字段登记隐藏后的校验/提交策略、上游变化影响，编辑不中断光标/输入法。
- 重复行使用稳定 ID，添加/删除/排序及跨行错误可追踪。选择器区分查询与已选草稿，取消不回填，确认检查候选仍有效且身份正确。
- 上传区分选中、等待、传输、成功、失败；已删除项的迟到回调不得复活。富文本保留工具栏/选区、批准格式与清洗，预览不发布，历史按业务约定。
- 通用手工排序使用操作列“排序”拖拽手柄，按住拖动并显示目标/落点，提供等价键盘操作；不令整行拖动妨碍选字/普通动作。按稳定 ID、明确筛选/分页范围，登记草稿或即时生效，取消/失败恢复；业务字段排序作为独立要求。

#### 15.6.4 反馈、复制与工具

- 行内反馈靠近字段/任务；关键错误持续可见。普通成功 toast 建议 3 秒，在所属宿主内避开动作/焦点，使用状态语义并清理计时器；不以易消失 toast 单独承载错误或决定。
- 复制须实际写入成功才提示成功，内容范围获准且不擅自解除脱敏；能力拒绝提供选择文本等替代。外部动作区分准备、尝试、返回、已核验，无能力时备用路径，传递正确对象参数并恢复现场；未知不伪造终态。
- 阅读器核对全文、目录/跳转、历史/滚动、下载来源，关闭不产生业务副作用。图示核对真实渲染、缩放/复位/滚动、图源与关闭恢复；打开图源不等于渲染通过。

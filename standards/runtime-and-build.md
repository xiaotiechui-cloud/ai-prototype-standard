## 13. 交互运行时契约

本章规定生成 HTML 时必须具备的状态与行为契约。实现语言不限，但语义必须一致。

`RV`、`ADM_RT`、`data-act`及相关函数/字段名构成既有共享运行时方案；采用该方案须保持接口。新项目可采用等价实现，在 01/03 记录方案版本、状态/动作/目标ID映射、可测试入口和差异，不强制所有AI使用相同函数名或内部代码。以下行为契约对所有方案有效；源码命名或测试接口存在均不证明真实交互通过。

### 13.1 全局评审状态（RV）

至少包含：

```text
end                 当前端
pageId              当前页面
state               当前页面状态
sim                 模拟结果（ok/fail/timeout/empty）
selectedComponent   当前所选组件
outline             描边开关
from                来源页面（返回用）
notes               评审注释（按页面/组件归属）
readerOpen          阅读器开关
readerDoc           当前文档
readerHist          文档历史
readerScroll        阅读位置
session             业务会话（登录、实名、绑定、订单、搜索历史等，仅内存）
```

规则：

- 评审状态与业务会话分开；
- 切换端/页面时清理不适用的旧状态；
- 业务会话默认只在内存中，不写 localStorage、不落盘；
- 状态预设进入瞬态后，切页/切状态要清除瞬态。

### 13.2 页面运行时（ADM_RT）

每个后台页面独立维护：

```text
draft          草稿字段
committed      已提交筛选
tab            当前页签
page           页码
size           每页条数
sel            当前选择
loading        查询中
error          查询失败
noperm         无权限
drawer         弹窗开关
drawerId       当前记录 ID
msg/msgKind    工作区提示
reqVer         请求版本（迟到响应作废）
advOpen        高级筛选展开
exportState    导出状态
```

页面专属草稿（如商品编辑、协议编辑、角色权限、退款、通知模板）放入同一运行时对象；按 `STD-RT-001` 实际完成关闭后清理，退出被阻止或选择继续编辑时不清理。

### 13.3 动作分发

<!-- RULE-ID: STD-ACT-001 -->

- 既有运行时的可点击动作通过统一的 `data-act` 分发；等价实现须登记对应入口和处理路由；
- 使用 `adm-` 前缀时，它是后台动作保留命名空间，必须整体转交后台分发器；
- 既有运行时的侧边菜单本地动作使用 `sb-` 前缀；
- 页面导航使用 `go`/`data-to`；
- 返回使用 `back`，按当前端与来源解析；
- 动作处理必须：

```text
读取参数 → 校验前置 → 修改草稿/状态 → 同步 DOM 或重渲染 → 反馈 → 导航/关闭
```

- 无匹配动作必须显式失败（开发期报错），不得静默吞掉；
- 写入类动作不得只改提示而不改数据；查看/预览/取消按职责保持业务数据不变，不能为证明“有结果”而建单、建批次或推进状态。
- 验收从真实入口追踪到分发、守卫、数据变化、界面结果及恢复；出现确认层、选项变化或 toast 均不能单独证明动作完成。
- 二次确认暂存并原样执行对象 ID 与全部参数：打开前不变、取消不变、确认一次只执行一次，目标失效时报错。分发器与确认重放器须做连通检查，未定义处理函数与未匹配命名空间显式失败。

动作契约分别声明读取对象、写入/状态迁移、产生物、外部调用及反馈依据。查看、导出、建批次、开始处理、确认完成可按已批准业务组合，但组合入口/确认须说明全部副作用；导出不自动等于交付完成，支付成功不自动等于交付成功。真实文件、模拟文件/任务、外部调用已发起与结果已确认应分别表述。剪贴板、下载、外部唤起等依实际 API/回执能力给出结果；仅已触发或浏览器已接受发起的，不得宣称外部动作已完成。不支持/失败/未知时提供当前能力可实现的恢复路径。

允许明确的离线模拟，不要求原型接真实支付/上游服务；浏览器发起下载通常不能证明最终落盘。纯查看仍不写业务数据；具有写入的组合动作不得标成纯查看。配置生产消费与快照边界按第3.4节，字段空值按第24.5节，保存/发布及部分结果按第12.11节；具体契约沿用项目04/05/03唯一来源，测试按第29章执行。

### 13.4 事件绑定顺序

1. 点击事件先处理二次确认：带 `data-confirm` 且不是确认层自身的动作，拦截并打开确认层；
2. 原生输入及其关联 label 保留默认行为，尤其复选框/单选框不得被全局 `preventDefault`；
3. 其他动作再 `preventDefault` 并分发；
4. 筛选输入由 `change`/`input` 更新草稿，点击查询或 Enter 才提交；
5. 弹窗内滚动由独立容器处理，背景滚动锁定；
6. Esc 只交由当前最上层处理，按 `STD-RT-001` 关闭或拦截；不按弹层种类跨层关闭。

真实入口验证包含 checkbox/radio 的直接点击与关联 label 点击，以及文件选择的鼠标和键盘入口。文件选择至少覆盖选择、取消、同文件重选、预览、保存重开与失败保留；不以程序赋值代替用户入口。不强制某一种 input 覆盖或关联技巧。

### 13.5 输入与草稿

- 输入事件只更新内存草稿，**不整页重渲染**，避免丢焦点与光标；
- 搜索子层只替换结果列表，不重建搜索框；
- 数字/金额输入即时清洗非法字符，但不擅自四舍五入；
- 选择/多选/拖拽优先局部更新；需重渲染时保留草稿、焦点/光标与滚动，评审工具另遵循 `STD-RV-001`；
- 关闭/取消时按规则保留或清除草稿；提交成功必须清空；
- 未保存退出统一遵循 `STD-RT-001`，PRD 的显式覆盖在 01 登记；
- 素材预览按稳定 ID 关联，排序/删除后仍对应同一项或明确回退；仅内存预览如实标注，不冒充服务端上传或持久化。

业务草稿、查询和操作目标须能确定所属端、账号/角色、稳定对象及来源；按能力登记同对象重开、异对象进入、取消、返回、成功后重入时的保留/清除策略。显式指定对象失效时按第12.6节报错，不回退其他记录。恢复查询、页码、选择范围、滚动和焦点时须遵循各自契约，不能只恢复 pageId 就声明现场恢复。评审工具引起的查看/选择继续以 STD-RV-001 为唯一快照权威；业务页面不直接套用工具的全部保留策略。

同对象重开的保留策略由项目契约决定，不要求所有表单永久保留草稿；账号切换的清理与共享遵循项目数据范围。保留输入不等于保留此前资格或授权通过，执行时仍校验。

### 13.6 异步与迟到响应

请求发起时固定本次不可变身份及适用上下文，回调比较该次身份与当前有效身份；不得比较两个会随新请求同时变化的对象字段。重置、离页/返回、账号/端切换、关闭后重开仍须使旧请求失效，避免计数归零后复用旧身份。可采用生命周期代次、持续递增标识、取消及等价隔离方案，不以是否存在特定字段判合格。验证至少包括同页乱序和“旧A未回→重置/关闭→新B→A返回”，检查数据、loading、提示、导航及操作目标均未被A改变。

- 请求上下文绑定端、页面、对象和生效版本；切换筛选时旧回调也必须失效；
- 超时不等于服务端失败；写操作重试前需查询/幂等依据；
- 处理中禁用重复提交；按钮文案切换为“提交中…”；
- 需要在本地模拟延迟时，使用明确的模拟状态，不阻塞浏览器。

纯同步能力可注明异步隔离不适用；异步查询、写操作及模拟计时器按实际生命周期验证。离开后是否继续后台请求按业务契约决定，但结果不得误写新上下文；不强制更名既有共享引擎字段。

### 13.7 重置与瞬态

- 重置清除：普通/高级条件、错误、选中记录、页码、弹窗、行选择，恢复默认页签与数据范围；
- 切页/切状态预设清除瞬态（NO_PERM/ERROR/LOADING 等），避免“切走再回来仍在错误态”；
- 刷新保留已提交查询上下文，重新请求；
- 页签/分页/筛选变化时按规则清理选择。

### 13.8 滚动锁与嵌套滚动

<!-- RULE-ID: STD-RT-001 -->

弹层生命周期与滚动锁的唯一归口：

- 区分业务画布宿主与评审视口宿主（第 15.5 节）；每层登记父层、触发元素、草稿、允许的关闭方式及所锁背景；
- 每个业务弹层声明所属业务画布/设备壳宿主，并以该宿主建立定位上下文；居中弹窗相对宿主居中，抽屉及底部面板相对宿主边缘定位。不得因挂载在文档根节点而意外相对整个 HTML 视口定位或遮住评审工具区；只有明确的全屏流程可声明视口宿主；
- 一次 Esc/遮罩事件只处理最上层。不可关闭的顶层消费该事件，不把事件传给下层；关闭子选择器不关闭父编辑层、不清空父草稿；
- 有修改未保存时，普通退出默认提示“放弃修改 / 继续编辑”；继续编辑不退出、不丢草稿。纯查看直接关闭。PRD 可显式覆盖，在 01 记录依据；
- 保存成功、保存失败、取消、关闭按钮、Esc、遮罩分别定义数据、草稿、焦点与滚动结果，复用同一生命周期；成功提交与就地动作仍按第 12.11 节；
- 打开时从对应宿主查找并锁定可滚动背景，必要时兜底到 html；记录原 overflow 与滚动位置，全部相关模态层关闭后才还原，不能关闭一个子层就解锁仍有模态层的背景；
- 弹层正文独立滚动并设 `overscroll-behavior:contain`，头尾/遮罩不带动背景；子层正文保持可滚，不用锁背景连带锁死正文；
- 焦点仅在最上模态层内循环，关闭子层回到父层触发入口，关闭全部后恢复原入口和背景位置；触发元素已移除时使用已登记的可达回退入口。

评审说明列的独立滚动与单栏回归页面流见第 8.4 节，不与本节模态锁混用。

### 13.9 计时器与轮播

- 所有计时器/轮播有启动、停止、清理；
- 页面切换、端切换、重置、弹层关闭时清理；
- 自动轮播在悬停、键盘聚焦、页面不可见时暂停；
- 手动切换后重新计时；
- 同一时间只允许一个轮播计时器；
- 不在定时器回调中引用已卸载页面的状态。

### 13.10 提示与焦点

- 工作区 toast 与评审 flash 分离；
- 成功/失败提示必须有可读文本，不只用颜色；
- 删除/确认取消后焦点回到触发按钮；
- 弹窗关闭后焦点回到触发入口；
- 阅读器关闭后恢复触发入口与页面滚动；
- 焦点样式与描边样式独立。
- 组件选择、描边、图示与阅读器遵循 `STD-RV-001` 的完整上下文隔离；焦点恢复不能代替草稿和滚动恢复。

### 13.11 HTML 安全

用户主动业务外链与运行资源依赖分别检查，判定按第 29.3 节；不自动加载外部页面、图片或脚本来完成原型运行。合法业务外链标明打开方式和离线/唤起失败的反馈或备用入口。

- 所有用户/模拟数据输出前转义；
- 富文本发布时清洗 `<script>` 与内联事件，再入库/展示；
- Markdown 渲染不执行原始 HTML/脚本；
- 链接协议只允许 `http:`、`https:`、`mailto:`、`#`；本地绝对路径不外跳；
- 图片缺失显示替代文本，不加载外链；
- 不把敏感数据写入 DOM 之外的可持久化位置。

### 13.12 无死代码与无死动作

- 删除功能后清理对应动作分支、数据、样式、文档引用；
- 保留但不展示的旧页面要标注“页库保留/侧栏已移除”，并确保不参与当前导航；
- 不保留“点了没反应”的按钮；
- 不保留从未被任何渲染读取的状态字段；
- 不保留重复监听器/重复计时器。
- 检查动作入口与实际分发、二次确认重放、状态消费均连通；语法通过不证明处理函数存在或 CSS 变量被图形消费，实际结果按 `STD-ACT-001` 验收。

## 17. HTML 单文件架构与构建

### 17.1 产物约束

02 必须是：

- 单个 `.html` 文件；
- 双击可打开；
- 不依赖网络、CDN、外部字体/图标/图片；
- 不依赖本地服务；
- 不发起真实业务请求；
- 内含全部页面、状态、组件说明、图示、交付文档；
- 推荐 Chrome/Edge/Firefox 较新版本。

### 17.2 模块分层

| 层 | 内容 | 职责 |
| --- | --- | --- |
| L0 | 样式与令牌 | 页面背景、评审外壳、客户端/后台布局、组件样式、阅读器、图示 |
| L1 | 评审外壳 | 标题、控制区、模拟身份、状态块、画布、说明列、图示/阅读器入口 |
| L2 | 核心工具 | DOM 选择、转义、金额、Markdown 渲染、安全 URL、图示查表 |
| L3 | 客户端渲染 | 移动端/桌面端页面渲染函数、共享 UI 组件 |
| L4 | 后台数据 | 菜单、订单、商品、角色、字典、模拟数据 |
| L5 | 后台配置与引擎 | 运行时、筛选、页签、表格、分页、弹窗、确认、toast |
| L6 | 启动与分发 | 页面注册表、路由、动作分发、后台动作、输入监听、初始化 |
| L7 | 注入数据 | 组件十节、图示 SVG/图源、文档全文/下载 |

**依赖方向：** 上层可调用下层；下层不得依赖上层业务页面。客户端与后台尽量隔离，避免共享全局变量造成冲突。

### 17.3 模板分片建议

```text
01-head.html        样式与设计令牌
02-shell.html       评审外壳（标题/控制/状态/画布/说明/图示/阅读器）
03-core.js          基础工具、Markdown、图示查表
04-client-a.js      客户端共享件与前半页面
05-client-b.js      客户端后半页面
06-web.js           桌面 Web 页面
07-admin-data.js    后台数据与菜单
08-admin.js         后台运行时、通用函数与第一组页面配置
09-admin-b.js       后台第二组页面配置与专属渲染
10-admin-render.js  后台通用渲染器
11-boot.js          页面注册表、路由、评审控制、动作分发、初始化
```

分片不是强制的，但必须保证：

- 页面注册表集中维护；
- 通用渲染器与数据分离；
- 动作与渲染无循环依赖；
- 构建后脚本顺序正确、无重复定义。

### 17.4 构建步骤

1. 读取模板分片并按顺序拼接；
2. 从页面注册表统计页面数，注入标题区（不得写死）；
3. 解析 03 的组件标题与十节，生成 `COMP_DOCS`；
4. 从 04/05 提取 `plantuml` 图源，构建期渲染为 SVG；
5. 清洗 SVG 内部 ID，按图号加前缀，保证全文档唯一；
6. 读取 9 份 MD，解析版本/批次，生成 `DOCS`；
7. 注入 `COMP_DOCS`、`DIAGRAMS`、`DOCS`；
8. 输出 HTML 与构建报告；
9. 执行语法/离线/渲染检查。

### 17.5 内嵌注册表

```text
window.COMP_DOCS  = { 组件ID: { id, name, sections: [{n,title,md}], source } }
window.DIAGRAMS   = [ { id, title, from, src, svg, w, h } ]
window.DOCS       = [ { file, md, ver, batch } ]
```

要求：

- 组件十节必须完整；缺节时报构建告警并阻断交付；
- 图示必须有图源与 SVG；缺图时给明确占位；
- 文档必须有原文与版本信息；下载内容必须是原始 MD；
- 注入 JSON 时转义 `</`，避免提前闭合脚本标签。

### 17.6 离线与安全

- 不引用 `http(s)` 资源；
- 不引用外部脚本/样式；
- 不加载外部图片；缺失图片用文字占位；
- Markdown 渲染不执行原始 HTML/脚本；
- 链接只允许安全协议；本地绝对路径不跳转；
- 富文本发布前清洗脚本与内联事件；
- 不在原型中持久化敏感测试数据。

### 17.7 性能与容量

- 单文件宜控制在可双击打开的合理大小（参考实现约 5.7 MB）；
- 内嵌 SVG/文档较多时，避免重复字符串与重复 ID；
- 大图/长文档按需打开，不平铺在主页；
- 渲染函数避免每次输入都整页重建；
- 页面切换后清理计时器与旧回调。

### 17.8 构建源不交付

以下内容不得进入交付目录：

- `_work/` 模板与脚本；
- PlantUML jar 与渲染缓存；
- 临时检查脚本、备份文件、对比文件；
- 旧版本分片。

构建脚本应在 00 中说明“构建期使用、不随交付提供”，但不得要求评审者运行脚本才能打开原型。

### 17.9 设计师共用

- 默认只交付一份 02，产品、研发、设计师共用；
- 02 必须保留页面/状态/组件稳定 ID（页面注册表、`data-component`），便于设计师脚本抽取；
- 不默认生成设计师专属 HTML、单画面 HTML、独立画面映射、导入 ZIP 或交接 ZIP；用户明确要求时才从同源定义导出；
- 设计师自行处理脚本抽取、Figma 导入、可编辑图层与连线，不属于默认验收任务；
- 原型本身的交互与布局错误仍须修复，不能归因于设计师脚本；
- 页面/组件变化后同步更新同一份 02 与相关 MD；
- 如需本地字体/图片，在 00 说明所需目录；不得因“只有一份 HTML”而遗漏依赖或改成联网；
- 若实际协助验证了脚本/Figma，须单独记录工具、方法与结果，不能把浏览器通过写成 Figma 通过。
